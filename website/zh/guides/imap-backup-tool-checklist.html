IMAP 备份工具：该看哪些地方

8 分钟阅读

市面上的 IMAP 邮件备份和归档工具很多，从免费的开源小工具到每年上千的企业归档套件都有。多数营销页面看起来几乎一模一样 —「安全」「可靠」「轻松备份」。真正重要的差别藏在营销文案底下，藏在关于文件格式和数据归属的决定里，而这些你往往要等到已经把身家托付给某个工具之后才会发现。下面是真正该检查的东西。

1. 它到底把邮件存成什么格式？

这是最重要的一个问题，也是多数人跳过的一个。问自己：如果我明天不再用这个工具了，还能用别的东西打开我归档的邮件吗？

  • 一个个独立的 .eml 文件（RFC 5322） — 最好的结果。每封邮件都是自己的标准文件，任何邮件客户端、甚至文本编辑器都能打开。什么都没被锁住。
  • Mbox — 每个文件夹一个大文件，把所有邮件串在一起。它是标准格式，支持面也广，但不导进某个客户端就没法直接浏览。
  • 专有的数据库或容器格式 — 最糟的结果。你的归档只有通过那个特定工具才用得了。如果那家公司关门，或者你停止付费，你可能实际上就进不去自己的备份了。

2. 归档到底存在哪里？

本地优先的工具会把文件直接存到你掌控的磁盘文件夹里。基于云的归档服务则把你的邮件存在它们的服务器上，这意味着你备份的可用性取决于那家公司是否还在经营、你的订阅是否还有效。两种做法本身都没错，但你应该清楚自己拿到的是哪一种 — 一份停止付费就消失的「备份」，其实不是备份，是订阅。

3. 它的认证方式做得对吗？

尤其是对 Gmail 和 Microsoft 账户，这个工具应该支持 OAuth2 登录，而不是要你的明文密码或应用专用密码 — 出于安全原因，两家服务商都在逐步远离基于密码的 IMAP 访问，有些账户甚至已经完全不支持了。对于像 Yahoo 这类不提供应用专用密码的服务商，工具需要支持它们的标准登录流程；如果一个工具对 Yahoo 只有「生成一个应用专用密码」这一个选项，说明它没跟上 Yahoo 如今真正的认证方式。

4. 能有选择地归档，还是只能全有或全无？

好的工具让你挑特定的文件夹、标签或日期范围。这比听起来更重要 — 如果你只想归档并清掉两年以上的邮件，全有或全无的导出会逼你把一切都下载下来（还要手动翻），包括那些你根本不用碰的邮件。

5. 它能忠实保留附件和排版吗？

在把重要东西托付给某个工具之前先测一下：归档几封带附件、带 HTML 排版的邮件，然后再打开它们。附件应当完好且能打开，HTML 邮件的显示效果应当接近原样，而不是被砍成纯文本。

6. 源代码可审计，还是你在信一个黑箱？

邮件天生敏感 — 财务记录、私人往来、工作沟通。开源工具让你（或你信任的人）真正核实软件拿你的数据做了什么，而不是只听厂商的一面之词。对备份工具来说，这一点比几乎任何其他类别的软件都更重要，因为你交给它的正是你最私密的信息。

7. 继续用你自己的备份要花多少钱？

有些归档服务光是让你能继续访问已有的备份就要持续收费，等于把你自己的数据租回给你。一个把邮件存成你磁盘上开放标准文件的工具没有这个问题 — 邮件一旦存下来，有没有这个工具你的归档都照样能用。

常见问题

做邮件备份时，.eml 和 .mbox 有什么区别？

一个 .eml 文件装一封邮件，几乎任何邮件客户端都能单独打开它。一个 .mbox 文件把很多封邮件打包成一个大文件，它是标准格式，但不先导入客户端就没法直接浏览。

基于云的邮件归档服务等同于本地备份吗？

不等同。云归档服务把你的邮件存在厂商的服务器上，所以能否访问取决于你是否继续订阅、厂商是否还在经营。本地备份把文件存到你掌控的磁盘上，与任何持续订阅无关。

对 IMAP 备份工具来说，支持 OAuth 为什么重要？

Gmail 和 Microsoft 账户越来越要求用 OAuth2 登录，而不是明文密码，有些账户甚至完全不支持基于密码的 IMAP 访问。没有正确 OAuth 支持的工具，可能根本连不上这些账户。

邮件备份工具应该是开源的吗？

这是一个很大的加分项，但不是硬性要求。因为邮件备份涉及高度敏感的个人和财务信息，开源代码让你（或你信任的人）能真正核实这个工具拿你的数据做了什么，而不是只能靠信任。
