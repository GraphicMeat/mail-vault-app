常见问题

关于 MailVault，你需要知道的一切。

MailVault 是一款免费开源的桌面邮件客户端，支持 macOS 和 Linux，把你的邮件存放在你自己磁盘上的保险库里。它通过 IMAP 连接你的邮箱账户，把所有邮件以标准 .eml 文件（RFC 5322）的形式，按 Maildir 格式存在你的电脑上，给你一份长久的离线备份，且不被厂商锁定。

MailVault 用 IMAP 协议连接你的邮件服务器，把每封邮件下载成一个标准的 .eml 文件，按 Maildir 格式存在你的 Mac 或 Linux 机器上。每封邮件就是磁盘上的一个文件 —— 人可以直接读、可移植，任何邮件客户端都兼容。邮件进了保险库之后，你就可以删掉服务器上那份来腾空间；本地这份不受影响。

MailVault 支持任何提供 IMAP 的邮件服务商，包括 Gmail、Outlook、Yahoo Mail、iCloud Mail、ProtonMail（配合 Bridge）、Fastmail、Zoho Mail，以及任何支持 IMAP 的自建或企业邮件服务。

MailVault 的核心功能是免费的，包括邮件阅读、撰写、搜索、会话归并、本地归档和手动备份。Premium 功能 —— 定时自动备份、跨账户邮箱迁移和自动清理规则 —— 需要 $4/月 或 $25/年；年付方案含 14 天免费试用。源代码在 GitHub 上。详情见完整定价。

你的保险库就是你 Mac 或 Linux 机器上的一个文件夹，里面是按 Maildir 格式组织的标准 .eml 文件 — 一封邮件一个文件，不需要数据库。你的数据从不离开你的电脑，也从不上传到任何云服务。因为 .eml 是通用标准，你的邮件可以用 Apple Mail、Thunderbird、Outlook 或任何其他邮件客户端打开 —— 你永远不会被 MailVault 锁住。

目录结构：

~/Library/Application Support/com.mailvault.app/
└── maildir/
    └── you@example.com/
        └── INBOX/
            ├── headers.json          ← cached list for fast loading
            └── cur/
                ├── 1234567890.eml    ← auto-cached email
                └── 1234567891_AS.eml ← archived + seen email

.eml（RFC 5322）是邮件消息的互联网标准格式。每封邮件 —— 邮件头、正文和附件 —— 都存成一个自包含的文本文件。与专有数据库不同，.eml 文件能被任何邮件客户端（Apple Mail、Thunderbird、Outlook）打开，也能用任何文本编辑器阅读。

Maildir 是一种久经考验的邮件存放目录结构，邮件服务器已经用了几十年。每封邮件就是一个文件，所以不存在一个会整体损坏的数据库 —— 一个文件坏了，归档的其余部分毫发无损。.eml + Maildir 合在一起，意味着你的邮件面向未来、可移植，永远不会被任何单一应用锁住。

文件名标记：

MailVault 在 .eml 文件名后面追加标记字符来记录状态：A = 已归档，S = 已读，R = 已回复，F = 已加标记。例如 1234567890_AS.eml 表示这封邮件已归档且已读。

MailVault 在设计上以隐私为先。你的邮箱凭据保存在 macOS 钥匙串或 Linux Secret Service 中，绝不会写进明文文件。所有数据都留在你的机器上——没有云同步、没有跟踪、没有分析统计，也没有数据挖掘。应用是开源的，你可以自己核对代码。

你可以这么做：

  • Microsoft 365 商业版/企业版账户不受影响 —— 组织账户的 OAuth2 一切正常
  • 关注这个问题 —— 这是只有 Microsoft 才能修的服务器端问题。Microsoft Q&A 讨论帖在跟踪进展
  • 个人账户在此期间先用 Outlook 网页版或 Microsoft 官方应用
  • MailVault 这边已经就绪 —— Microsoft 一旦修好，MailVault 的 OAuth2 登录立刻就能用，不需要做任何改动

技术细节：MailVault 用的 OAuth2 实现与 Mozilla Thunderbird 相同，遵循 Microsoft 官方的 IMAP OAuth2 文档，采用 PKCE 和 XOAUTH2 认证。

Proton Mail 对邮件做端到端加密，所以不直接开放 IMAP。要把它接到 MailVault（或任何第三方邮件客户端），需要 Proton Mail Bridge —— 这是 Proton 提供的桌面应用，跑在你自己的电脑上，把你加密的邮箱以标准 IMAP/SMTP 的形式暴露在 127.0.0.1 上。Bridge 需要付费的 Proton Mail 套餐；免费版用不了。

设置步骤：

  1. 从 Proton 官网安装 Proton Mail Bridge
  2. 用你的 Proton 账户登录 Bridge
  3. Bridge 会为每个账户显示一组 IMAP/SMTP 凭据 —— 显示出来的那个密码是 Bridge 生成的应用密码，不是你平常的 Proton 账户密码
  4. 在 MailVault 中，从服务商列表里选择 Proton Mail Bridge （如果列表里没有，就选 自定义 IMAP ），然后填写：
    • 服务器： 127.0.0.1
    • IMAP 端口：1143，安全方式：STARTTLS
    • SMTP 端口： 1025
    • 用户名：你的 Proton 邮箱地址
    • 密码：第 3 步中 Bridge 生成的密码

MailVault 同步的时候，Proton Mail Bridge 必须在后台运行 —— Bridge 关了，MailVault 就够不到邮箱。不过就算 Bridge 关着，你已经归档的邮件在 MailVault 里照样能完整地阅读和搜索，因为 MailVault 是本地优先的，它读的是自己的 .eml 存储，而不是实时向 Bridge 要。

Bridge 用一张自签名 TLS 证书来保护它本地的 IMAP/SMTP 服务。对本地（127.0.0.1）连接，MailVault 会自动处理这一点，不需要你手动安装证书。

查找并验证地址：

  • 建议 — MailVault 会给出它在你自己的邮件里见过的地址：你以前用来发过信的，以及别人寄给你的邮件所落到的那些地址。
  • 验证 — 用这个地址发一封测试邮件，默认寄到你自己的邮箱，这样你在真正依赖它之前就能确认服务商接受它。
  • 如果被拒绝 — 这个地址必须是你的服务商允许该登录身份用来发信的别名或身份。Fastmail 接受账户上的任何别名；Gmail 需要先在 Gmail 设置的“以此地址发送邮件”里添加该地址；Microsoft 365 则需要管理员授予 Send As 权限。

别名是在你的邮件服务商那里配置的，不在 MailVault 里 — MailVault 只会以服务商已经授权的地址发信。

MailVault 需要 macOS 11（Big Sur）或更高版本，在 Intel 和 Apple Silicon 上都原生运行。Linux 上提供 .deb、AppImage、Snap 和 Flatpak，适用于 Ubuntu 22.04+ / Debian 12+。它常驻菜单栏，窗口关闭后仍会继续同步。

附件以 MIME 部件的形式嵌在每个 .eml 文件里 —— 它们不是单独存放的文件。你打开一封邮件时，MailVault 的 Rust 后端会解析 MIME 结构并即时取出附件。你可以直接在邮件查看器里对任何附件执行打开、另存为或在文件夹中显示。取出来的附件会临时缓存，方便再次快速访问。

归档会从你的服务器下载完整邮件（如果尚未缓存），并把它存成磁盘上的一个 .eml 文件，文件名里带 A（已归档）标记。如果这封邮件本地已经缓存过，MailVault 只是给文件改个名，加上归档标记。归档过的邮件会出现在保险库视图中，并被纳入备份。在你自己动手删除之前，服务器上那份不会被碰。

归档并删除按顺序做三件事：把邮件作为 .eml 文件复制进你的保险库，核对这份副本确实在那里，然后才从服务器上删除。任何没通过核对的都会留在服务器上 — 复制失败绝不会让你搭上原件。做完之后，这一行会显示你的唯一副本：保险库是这封邮件仅存的地方，这也提醒你该把备份盘接上。

MailVault 把你的邮件导出成一个 ZIP 压缩包，里面是全部 .eml 文件，外加一份 manifest.json，它按邮箱地址（而不是内部 ID）把邮件对应到账户，所以备份在不同的安装之间是可移植的。你可以选择导出全部邮件或仅已归档的。导入是幂等的——如果某封邮件本地已经有了，就不会重复一份。如果备份里含有你还没设置过的账户的邮件，MailVault 会自动创建这个账户（你只需在设置里重新输入密码）。

Google 限制单个 Gmail 或 Google Workspace 账户每天可以传输多少邮件数据。限制针对账户，而不是应用——Apple Mail、你的手机和 MailVault 共用同一份每日额度。

访问方式 下载限额 上传限额
IMAP （MailVault 使用） 2500 MB / 天 500 MB / 天
POP 1250 MB / 天 —
Gmail 网页客户端 750 MB / 小时，1250 MB / 天 300 MB / 小时，1500 MB / 天

一旦超出限额，Google 会临时暂停该账户：通常在 1 小时左右，但也可能持续到 24 小时。所有 Google Workspace 版本的限额都一样，而且 Google 可以不经通知就修改——当前的具体数字见 Google 的带宽限额文档。

这对第一次备份意味着什么。超过大约 2.5 GB 的邮箱没法在一天之内通过 IMAP 下载完——没有哪个客户端做得到，这是服务器端的硬性上限。大的归档要做好花上几天的准备。

MailVault 的做法。它会识别出限额响应，干净地停下这一轮，而不是不断重试把封禁拖得更久，并告诉你已经触到当天的限额。等暂停解除后再启动备份，它会从停下的地方继续——本地已经存好的邮件会被跳过，不会下载两遍。等待期间，磁盘上已有的一切照样能读、能搜。

MailVault 始终在应用自己的存储里保留一份邮件的工作副本——你读的、搜的、打开的就是它。外部备份位置则在你掌控的磁盘上再加一份独立的第二副本：一块外接 SSD、一个 NAS 共享目录，或者一个同步文件夹。

  • 与工作副本同时写入。备份运行时，每封邮件都会同时存到两个位置，用的是同样的 .eml + Maildir 布局——所以没有 MailVault，第二份副本也能用 Apple Mail、Thunderbird 或任何其他客户端打开。
  • 是冷存储，不是镜像。应用日常不会去读它。在服务器上删掉的、或者在 MailVault 里移除的邮件，仍然留在这份外部副本里。
  • 已读和未读标记双向保留。每次运行前两份副本会先对账，所以你读过的邮件仍然是已读。
  • 独立于应用之外。就算那台电脑坏了，或者你卸载了 MailVault，那个外部文件夹依然是一份完整的、自我描述的邮件归档。

在设置 → 备份 →“第二副本——外部冷存储”里设置，任选一个文件夹。在 macOS 上，MailVault 会为该文件夹保存一个安全作用域书签，这样重启和应用更新之后访问权限依然有效——单纯记一个路径做不到这点。状态标记会显示就绪、需要重新授权、不可用或访问被拒绝，重新授权只需点一下。

如果备份过程中拔掉了磁盘，工作副本仍会正常完成，MailVault 会报告有多少封邮件没有写入外部副本。下一次运行会把它们补上——不会丢东西，失败也绝不会悄无声息。

可以。默认情况下，MailVault 把邮件存储放在启动磁盘上应用自己的 Application Support 文件夹里。你可以把这个存储移到任意磁盘上的任意文件夹——外接 SSD、第二块内置硬盘——当归档增长到几十 GB 时，这一点就很重要。

只有邮件数据会搬走：邮件本身、邮件头缓存、附件缓存和文件夹列表。账户、设置和日志留在应用自己的文件夹里，这样 MailVault 总能启动到足以告诉你某块磁盘不见了，并再次向你要那个文件夹。

删除任何东西之前，搬迁会先经过校验。MailVault 把所有内容复制到新文件夹，核对每个文件都以正确的大小到位，切换过去，然后才删掉原件。搬迁途中断开连接或崩溃，当前的存储不会受损；再跑一次，它会接着来，而不是把已经复制好的重来一遍。

文件夹带有标记，可被识别。一个小小的标记文件标识着这份存储，所以你之后重新接上磁盘、或者手动挪动了文件夹，都可以把 MailVault 重新指向它；而如果一个文件夹属于另一份存储、或者里面根本没有邮件，MailVault 会拒绝它。

如果磁盘没有连接，MailVault 会报告邮件存储不可用，而不是悄悄在默认位置另起一份归档，最后留给你两份各半的副本。重新接上磁盘，或者再选一次文件夹。你也可以随时切回默认位置——在你动手搬之前，邮件一直待在原处。

这和第二副本不是一回事。它改的是当前存储所在的位置。外部备份位置是在它之上再加一份冷副本。两者一起用——邮件存储放在快速的外接 SSD 上，冷副本放在 NAS 上——是个合理的配置。

因为机器上没有拼写词典。macOS 和 Windows 随系统自带词典；Linux 上的词典来自你的发行版，而最小化的桌面安装往往一个都没有。MailVault 通过 WebKitGTK 做拼写检查，后者经由 enchant 和 hunspell 查词——所以只有装了 hunspell 词典才能画出下划线。

邮件工具栏上的那个按钮会告诉你处在哪种情况。装了词典时，它用来开关拼写下划线，MailVault 会记住这个设置。一个词典都没有时，它会打开这份说明，而不是假装自己是个开关。

为你的语言安装词典：

Debian、Ubuntu、Mint
sudo apt install hunspell-en-us
Fedora
sudo dnf install hunspell-en
Arch、Manjaro
sudo pacman -S hunspell-en_us
openSUSE
sudo zypper install myspell-en_US

把语言代码换成你自己的——hunspell-de-de、hunspell-fr 等等。你可以装好几个；MailVault 会用与系统语言匹配的那个来检查，如果都不匹配，就拿全部一起检查。装完后重启 MailVault——拼写检查器是在应用启动时初始化的。

snap 版是个特例。严格受限的 snap 看不到装在宿主系统上的词典，所以它自带一份。如果 snap 报告没有词典，改装 .deb 包——它会用你系统上已有的词典。
