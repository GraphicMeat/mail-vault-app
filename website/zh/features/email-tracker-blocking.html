那个在你打开邮件时回报消息的像素

多数营销邮件里都藏着一张 1×1 的图片。邮件一渲染，你的邮件客户端就会去请求它，而这个请求会告诉发件人你读了 —— 什么时候读的、读了几次、大概在什么地方。MailVault 会找出这些信标，并在邮件渲染之前把它们从 HTML 里拿掉，于是那个请求根本不会发生。

同一封订阅邮件，渲染两次。左边信标加载了，发件人被告知了。右边 MailVault 已经把它移除 —— 邮件的其他部分毫无变化。

跟踪代码长什么样

这是一个真实形态的信标，取自一份营销模板。它只有一行，它是隐形的，而且它就在一封你本来乐意收到的邮件底部。

那一个像素会告诉发件人什么

  • 你打开过它 以及之后你每一次重新打开。
  • 精确到分钟的时间 这也顺带暴露了你的作息时间和时区。
  • 你的 IP 地址 也就是说，你读它时大致在哪。
  • 你的设备和邮件客户端 从请求附带的 user agent 里读出来。

MailVault 是怎么找到它们的

已知的端点。MailVault 内置了一份将近 500 条打开跟踪 URL 模式的列表 —— Mailchimp、SendGrid、HubSpot、Mailgun、Klaviyo、Marketo、Salesloft、Superhuman、Mailtrack、Yesware，还有另外几百个。它把 MailTrackerBlocker（macOS Mail 的跟踪像素插件，其本身的数据源自 HEY 和 Simplify Gmail 的列表）的拦截列表与公开的 Ugly Email 列表合并，并补上了这两份列表出现之后才有的发件方。

为什么不用 Brave 或 Mozilla 的列表？那些是网页跟踪器列表 —— 浏览器在页面上拦截的脚本和信标域名。邮件的打开跟踪走的完全是另一套端点，所以上面那些专门针对邮件的列表，才真正拦得住进入你收件箱的东西。

形态。不在列表上的信标照样会露馅：声明为 1×1 的图片、用 display:none 藏起来的，或者塞在一个塌缩容器里的。你真正看得见的图片不会被动。

请求路径。那些只用来发信标的路径 —— /open、/pixel、/wf/open —— 即便来自一个还没人收录过的域名，也会被标出来。

这一切都在本地完成。拦截列表随应用一起分发，在版本更新中同步。MailVault 从不在运行时去取列表，也从不上传你邮件的任何部分：一个要打电话问服务器该拦哪些像素的应用，不过是把一个跟踪器换成了另一个。

问答

拦截会把邮件弄坏吗？

不会。跟踪像素在设计上就是隐形的 —— 移除它不会改变任何你看得见的东西。真正的图片、徽标和照片都不会被动。

那些被跟踪的链接呢？

MailVault 免费的链接安全扫描已经会标记出经由跟踪域名跳转的链接，并在你打开之前给出警告。跟踪拦截处理的是那些完全不用你点击就会触发的信标。

我还能看到被拦掉了什么吗？

能 —— 那个图标会变成一只被划掉的眼睛，并列出每一个被移除的信标，含厂商和 URL。设置里的「跟踪拦截」页面还会累计显示在你邮件中一共发现了多少。

这在 Linux 上和 macOS 上一样管用吗？

一样。它是邮件渲染器的一部分，所以在两个平台上的行为完全相同。
