Changelog

New features, improvements, and fixes in every release.

v2.11.0 August 31, 2026 Latest

Added

  • Double-click an account in the sidebar to go straight to its inbox. One click on an account takes you back to whichever folder you were last reading in it, which is what you want most of the time and the wrong thing when what you actually want is new mail. Double-click now goes to that account's Inbox, from anywhere — another folder, another account, or the All Inboxes list.
  • Any message or thread can now be saved as a picture or as a single web page. Mail is the one archive most people cannot hand to anyone else: forwarding it changes the headers, a screenshot cuts off at the window edge, and printing to PDF renders whatever the printer stylesheet felt like. MailVault now exports a message, or a whole conversation, as a PNG image of exactly what you were reading — or as one self-contained HTML file. The HTML folds every message in the thread behind a line giving its date and sender, so a forty-message conversation opens as a list you expand one message at a time, with the whole conversation listed down the left in date order — click any entry to jump to it — over a pair of buttons that unfold or fold all of it at once. It fits whatever window it is opened in, down to a phone, so there is never anything to scroll sideways; on a narrow screen the list moves above the conversation rather than squeezing it. There is nothing to fetch and no server to be alive: the single script in the file only sizes each message to the window and works those two buttons, and with scripting turned off the file still opens and every message still folds. Remote images are fetched once, during the export, and written into the file itself, so it still reads years later with the network unplugged — and every file says underneath which account and folder it came from, each message's identifier, and how many remote images were mirrored in, how many the sender's server would not give up, and how many tracking pixels were dropped rather than fetched. Nothing that can execute survives the export: an exported file is opened outside MailVault, where none of the protections around the reading pane apply, so scripts, frames and handlers are taken out before the bytes are written. A conversation too tall for one image is split into numbered pages rather than shrunk, because a soft picture is a worse record than a second file. Export sits in the open message's toolbar, in the thread header, in any row's menu and in the bar that appears when rows are ticked — and where a message's body is not loaded yet, MailVault fetches it the same guarded way the reading pane does, so a thread exports whole rather than half. This is a Premium feature; without a subscription the same button shows three samples MailVault renders on the spot with the very same code, which you can open or save to see exactly what you would get.
  • MailVault now speaks nine languages. The whole app — every screen, every button, every message it puts on screen, the menu bar and the tray icon's menu, the notifications it sends and the errors it reports when a mail server refuses something — is available in English, Spanish, French, Italian, German, Brazilian Portuguese, Japanese, Korean and Simplified Chinese. Pick a language in Settings and it changes as you watch: nothing to restart, nothing to reinstall. Dates, times and numbers follow the language you chose rather than the one your computer happens to be set to, which matters if you read English mail on a German Mac, or the other way round. The website is translated too — every page, in all nine, with screenshots taken in each language rather than English pictures under translated text, so what the page shows is what you will see. Nothing about this reaches the network: the translations ship inside the app, and choosing one tells nobody anything.
  • On Linux, MailVault now says why spelling is not being checked, and what to install. Linux has no spell checker of its own: the dictionary comes from your distribution, and a minimal desktop install often has none — which looks exactly like a button that does not work. MailVault now checks what is there. Where a dictionary is installed the red underlines appear and the toolbar button turns them off and on as usual; where none is, the button opens the instructions instead — the one-line install command for Debian, Ubuntu, Fedora, Arch and openSUSE, how to pick a different language, and a link to the guide on the website. When several dictionaries are installed, MailVault checks against the one matching your system language. The snap package now carries English dictionaries of its own, because a confined snap cannot see the ones installed on the rest of the system, and the .deb suggests one at install time.
  • MailVault now tells you when an email is watching you, and can stop it. Most marketing mail carries a hidden image, usually a single transparent pixel, that your mail program fetches from the sender's server the moment the message opens. That one fetch reports back that you read it, at what minute, how many times you came back to it, roughly where you were, and what you read it on — none of which you agreed to. Every message MailVault opens is now checked for those beacons, and a small eye appears beside the subject, on the row and above the open message, next to the marks for a faked sender and a mismatched reply address. Click it and MailVault names the company doing the tracking and shows the exact address the pixel would have called. That much is free, for everyone, forever. With a subscription MailVault also takes the beacon out of the message before it is drawn, so nothing is ever requested and the sender is told nothing at all; the eye closes to say so. It works in the reading pane, in threads, in Chat view and in a popped-out message window, and there is a Tracker Blocking screen under Features that shows the same email side by side, tracked and cleared, with the tracking code itself spelled out. Nearly 500 known tracking addresses ship with the app — merged from the MailTrackerBlocker and Ugly Email projects and extended with senders newer than both — and the screen links out to both projects, with their licences, so you can read the lists rather than take our word for them. The list is bundled and updated in releases. MailVault never asks a server which pixels to block: doing that would be one more thing reporting on what you read.
  • MailVault now introduces itself the first time you open it. A new install used to land on an empty mailbox list with an Add Account button and no explanation of what the app was for, which is a poor first impression for something whose whole point is that your mail stops living on someone else's computer. The first launch is now a short tour. It opens on the logo and asks which of the nine languages to use — asked, not guessed from the machine, because the language your computer is set to is often not the language you read mail in — and everything after that is already in it. Then it says, in four cards, what MailVault actually does with a mailbox and where the password goes: into the system keychain, not into a file the app writes. Adding a mailbox is one button on that page, and it opens the same account dialog as the sidebar does; there is also "I'll do this later" for anyone without their server details to hand, which carries on through the rest of the tour rather than dumping them at the end. Next it asks how the app should look, with a real message list beside the choice that changes as you pick — light, dark or following the system, and the density — so the decision is made by looking rather than by reading the names of the options. The last two pages say what is included for nothing and what a subscription adds, the second with pictures of each feature rather than a list of names, and anything there can be opened later from Settings -> Help without going through the tour again. While all of this is being read, MailVault is already fetching the first mailbox in the background, so finishing the tour lands on mail rather than on a spinner.
  • Settings -> Billing now says what a subscription buys. It quoted a price against nothing at all: the features it pays for were described on five separate locked panels scattered through the app and on the website, and nowhere in the tab that asks for the money. Billing now lists every Premium feature above the plan card, each with a line saying what it does and, where it has a screen of its own, a link straight to it. The list appears in every build, including the Mac App Store one, because a list of features carries no price. Settings -> Help gained the same gallery, and a link to the FAQ in the language the app is set to.
  • The FAQ is now six pages instead of one. Twenty-three questions on a single page meant scrolling past everything to reach anything. They are now grouped — getting started, storage and the vault, mail providers, Premium, backup and restore, and troubleshooting — behind a hub with a search box that filters the whole list of questions at once. Every answer is plain text that is always visible and needs no scripting to open, every page carries its own structured data so search engines can quote the answers, and old links into the single page still land on the right question.

Fixed

  • A message that refused to open now opens on the first try. Reading mail means asking the server for it, and MailVault keeps a few connections to your mail server open and reuses them rather than starting a new conversation for every message. A connection the server had quietly dropped in the meantime was still handed out, and the message opened onto "Server refused UID FETCH: connection lost". Pressing "Try again" worked — which made it look random — because the second attempt happened to get a fresh connection. MailVault now notices that the connection died under it and quietly asks again on a new one, so the first press is the only press.
  • "Mark as read" works on a message in your vault in the All Inboxes list. Ticking a message the vault holds and choosing "Mark as read" did nothing at all — no error, no change, the row stayed bold. Messages the vault holds and the mail server does not are kept in a different list inside MailVault from the ones the server just sent, and every read/unread change only ever touched the second one. The change now reaches both, and it is written into the vault's own record of the message, so it is still read after switching folders or restarting rather than quietly coming back unread.
  • An account switch is no longer overtaken by the one before it. Two switches in quick succession — which is exactly what a double-click is — could land on the first one's folder instead of the last one's. The switch that had already been abandoned still painted its own account and folder over the newer one on its way out, and then asked the server to refresh that folder as well. An abandoned switch now stops where it is told to.
  • Spellcheck marks misspelled words on macOS. The button that turns spellchecking off and on has been in the message toolbar since 2.10.4, and on macOS it never had anything to turn on: the checker built into the system stays off until an app asks for it, and MailVault never asked. Words went unmarked whichever way the button was set — the setting was real, the underlines were not. MailVault now asks at startup, so misspellings are marked the way they are in every other Mac app, and the button does what it has been saying it does.
  • Auto-cleanup rules now actually run — and every existing rule has been switched off until you say otherwise. The rules that archive or delete mail past a certain age were written down by the settings screen in one shape and read by the engine in another: it looked for fields the screen has never saved, worked out an age threshold of nothing, and stopped before touching a single message. Every rule anyone has ever created has been silently doing nothing, run after unattended run. Simply fixing the reader would have been worse than the bug — rules made months ago, watched to do nothing and forgotten would have woken up on the next launch and started deleting real mail with no warning. So the stored rules have been rewritten into the one shape and every one of them switched off, with a notice on the screen saying why. Turning one back on is a single toggle, and that is yours to decide. A rule the engine cannot make sense of is now skipped and reported rather than treated as though everything were old enough to go.
  • The rule editor no longer offers a folder the engine refuses to touch. Drafts could be picked, saved and switched on; the rule then sat there looking active and did nothing, because Drafts is protected and always has been. It is no longer in the list, and the two lists — what may be picked and what may be acted on — now come from the same place, so they cannot drift apart again.
  • A new message is sent from the account whose mail you are reading. Compose opened on whichever account sent the last message, so switching account in the sidebar and clicking Compose wrote from the account you had just left — a difference visible only in the From row, if you thought to look at it before pressing Send. A new message now starts on the account on screen, and in All Inboxes, where every account's mail is in one list, on the account of the last message you opened. An address you have chosen to send as is still remembered, on the account it belongs to. Replies, forwards and saved drafts keep the account they always had.

Changed

  • An open message no longer carries a second, quieter claim about where it lives. The band across the top of a message says where that message is kept — in your vault, on the mail server, or the last copy left anywhere — and a small symbol beside the sender's name said it again, a couple of centimetres below. The two were worked out differently: the band reads the same record as the row you clicked, while the symbol asked only whether the message was in the folder on screen. So a message the band called "Saved in your vault" wore a blue cloud that read "On the server — not saved to your vault yet". The symbol beside the sender is gone; the band is the message's one statement, and every row in the list keeps its own.
  • The “Report a bug” dialog now takes what should exist, not only what is broken. Someone who has just hit something wrong is the same person who knows what the app should have done instead, and that dialog is the only moment MailVault has their attention on the subject. It now offers “Suggest a feature” as its second row, filing into the Ideas section of the project’s discussions rather than Bug reports, and its heading says so. Email moved down below “Browse discussions”, because email is the private fallback and a public thread is the one the next person with the same problem can find — and the dialog now says what an email can cost: MailVault’s logs carry every address the app has seen, so a log is something you attach deliberately rather than by default. The dialog also carries a link to follow the project, and says who makes MailVault.
  • A locked feature now says what else Premium covers. Every surface that asks for a subscription carried its own short pitch for the one thing it was gating and nothing about the rest, so seeing the whole list meant going looking for it. They now share a single “See everything in Premium” link out to the feature page, and one locked screen is enough. App Store builds do not show it, for the same reason they do not show the price: that page carries the web subscription’s price, and a Mac App Store build must not advertise a purchase made outside it.
v2.10.4 August 27, 2026

Added

  • MailVault can now ask your mail server whether a message still exists anywhere on it. A message you have archived is shown in gold — "your only copy" — when the vault on this computer is the last place it survives. That claim used to be worked out from the folder the message was archived from, which is not the same question: archive a message on your phone and it leaves the inbox for All Mail, a rule files it under a label, a delete puts it in the Bin. In every one of those the mail is perfectly safe and the row went gold anyway, so the claim was withdrawn — and with it the alarm worth having, the one that says someone else deleted your mail and the vault is what is left. Open a message you have archived and the band above it now offers "Check the server". MailVault searches every folder on the account for that exact message, and says what it found: still on the server and which folder has it, or gone from all of them. Only the second answer turns the row gold, and only when every folder actually answered — a folder that refuses to open is reported as a folder that did not answer, not as an empty one. The verdict is written next to the message on this computer, so it survives closing the app, and MailVault runs the search by itself when a message you have archived disappears from the folder it was archived from.
  • Spellcheck can be turned off while you write. The toolbar in the message window has a new button at its right-hand end. Press it and the red underlines stop — in the message and in the subject line — and press it again and they come back. MailVault remembers which way you left it, so it stays that way for the next message and after a restart, rather than switching itself back on with every new window. The signature editor in Settings is the same editor, so it follows the same switch.
  • "Report a bug" now offers somewhere public to put it. The button in the sidebar opened a message addressed to one inbox: every report was a private thread between one person and the developer, and the next person to hit the same thing had nothing to search. It now asks where the report should land. "Report on GitHub" opens a new thread in the Bug Reports section of the project's discussions, where it is searchable and where you are told when it is fixed. "Email the developer" is the message as before, with the app version, platform and account details already filled in, for anything you would rather not post. "Browse discussions" opens the list, because the answer may be there already.
  • Refer a friend. A second button under it opens a new message with nothing filled in but the pitch: what MailVault does, the five things it is for, and a link to the site. Address it to someone and send.

Changed

  • A "your only copy" message no longer paints its whole row gold. The loudest surface in the app was spent saying something the row already said three other ways: the symbol beside the sender, the label on the open message, and the band above it. The gold wash also had to switch off the highlight that follows the pointer, so the one row you most wanted to click was the one row that did not respond to the cursor. The row now looks like every other row and behaves like one; the symbol, the label and the band still carry the claim.

Fixed

  • A reply leaves from the mailbox you were reading. Reply, Reply All and Forward opened on whichever account had sent the last message, not the one holding the message being answered — so an answer to mail in one mailbox went out under another mailbox's address, to a correspondent who had never written to it. A message opened from a mail server carries no record of which mailbox it came from, and that missing record was what the choice fell back on. The account the message is in is now kept with it, and reply and forward leave from that account. Only a brand-new message still opens on the account you last sent from.
  • The gold "only copy" mark stops going out — after an archive, and in search results. The mark that says the copy in your vault is the last one left is worked out from a record kept beside each message on this computer, and that record was not travelling with the messages. Two things followed. Saving, archiving or deleting anything in a folder made MailVault rebuild that folder's list from the stored messages alone, so the gold went out on every proven message in the folder — silently, until something else happened to reload them. And search results were built the same way, so a message MailVault had proved was the last copy left showed gold in its folder and plain grey one search away, which is the wrong way round: search is where you look for a message you are afraid has gone. The record now travels with the messages however the list is built, and a search result carries the same mark as the row it came from, whether you search one folder or all of them.
  • A backup that saved almost everything no longer reports itself as failed. If a mail server refused to hand over a single message — one that has been sitting there unread for years, one the server has trouble reading back — the whole run was reported as a failure, and the notification that arrived said "Backup failed" followed by the words "Unknown error", because nothing was passed along to say what had actually gone wrong. On 27 August that was a run which had saved 788 of 789 messages. A run that saves what the server gives it is now reported as what it is: the account is marked incomplete rather than failed, the notification says "Backup partially complete" and carries the count and the server's own words for the message that did not arrive, and the backup card in Settings shows the same. A run that saves nothing is still a failure, and still retries.
  • MailVault says when Premium stops applying to this computer. A subscription can end between one check and the next — it lapses, a payment fails, or the device loses its place to another machine. Until now nothing was said: the Billing tab quietly went back to reading "Free", the features that need Premium stopped, and the only way to find out was to notice something missing. MailVault now says so plainly in Settings → Billing, explaining which of those happened, and sends a notification so the message arrives even when Settings is not open. Automatic backups are deliberately left running — billing is never a reason to stop copying mail onto your own disk.
  • Automatic backups no longer run without a subscription. Asked by someone who wanted to know why backup notifications kept arriving on an install that had never signed in to a paid account. The per-account backup switches were gated; the "Automatic Backup" master switch above them was not — and that switch is an override that turns on every visible account at once, so a single flip on a free install backed up everything and announced each run, notifications being on by default. The check now sits on the one door every automatic run passes through, whichever of them wakes it. Manual "Back up now" is unchanged and still free. A schedule left behind by a subscription that has lapsed is kept rather than deleted: it stops running, and starts again untouched if you resubscribe.
  • The dot that means "your backup drive has this" no longer looks like the mark for "saved in your vault". Every row in the list carries a small symbol saying where that message lives: a cloud for one that is only on the mail server, a disk for one saved in your vault, and a different symbol again for the last copy left anywhere. A tiny dot beside that symbol says your external backup drive has a copy too. The dot was painted in the same green MailVault uses for the vault itself, so a message that was only on the server showed a green dot directly above the words "Not saved to your vault yet" — the colour said one thing and the sentence said the opposite. The dot now carries no colour of its own. Filled means the drive has it, hollow means the drive is not connected and there is no answer either way, and the colour belongs to the symbol it sits on.
  • An open message now says the same thing as the row you clicked to open it. The band above a message worked out where that message lives without ever asking about the backup drive, while the symbol beside the sender's name a couple of centimetres below it did ask. One could read "On the server" while the other read "On the server and backup drive", about the same message, at the same moment. Both now read the same record, through the same piece of MailVault. The band also names the vault in its first line rather than only in the small print: a message can be on your mail server and on your backup drive and still not be in your vault, and that is the fact worth reading first.
  • A message in Sent stops borrowing an inbox message's backup. Mail servers number messages within one folder at a time, so number 8 in your inbox and number 8 in Sent are two different messages. MailVault matched copies on the backup drive by that number alone — and the inbox view shows your replies from Sent inside its conversations, so a reply that had never been backed up could wear the mark of an unrelated inbox message that had. Backup copies are now matched by folder as well as by number, MailVault reads the Sent folder's backups alongside the folder you are looking at, and a message in a folder it has not read is reported as unknown instead of as "not on your backup drive" — an answer nobody had asked for.
  • MailVault stops mentioning a backup drive you never set up. The small dot beside each message's symbol has three states: filled when your backup drive holds a copy, hollow when the drive is not connected and there is no answer either way, and absent when there is no copy on it. MailVault could not tell "the drive is unplugged" apart from "there is no drive", so every message belonging to someone who had never chosen a backup location wore the hollow dot, and the message you opened said "Backup drive not connected — can't verify" — a complaint about a feature that had never been turned on. With no backup location configured, nothing is drawn and nothing is said. A drive that has been set up and is not reachable still reports itself as exactly that.
  • The line under the mailbox name says what it is counting. It read "1,213 of 1,630 loaded in your vault", which reads like something still loading, and it sat directly under another count whose "of" meant the whole mailbox on the server — two lines, two meanings, one word. It now reads "Vault: 1,213 of 1,630 loaded": of the messages MailVault has loaded into the list so far, that many are saved in your vault.
  • The whole app no longer slides out of its own window. MailVault fills the window exactly — nothing sits above the sidebar and nothing below the message list — so there is nothing to scroll. A firm two-finger flick on the trackpad dragged the whole app downwards anyway, leaving a band of empty black where the panes had been and no scrollbar anywhere to pull them back. The window itself now stays put. The message list, the open message and the folder list scroll exactly as before.
v2.10.3 August 26, 2026

Fixed

  • A message in a conversation stops showing its subject where its text should be. MailVault keeps a copy of every message you open on this computer, filed under the number its mail server gave it. Those numbers are only meaningful to one server: move a domain to a new mail host and the new server hands the same numbers to different messages, so the copy filed under a number is somebody else's mail. MailVault noticed that and gave up — and the conversation then printed the message's own subject line, in italics, exactly where the message should have been. It reads as an email one line long. MailVault now asks the server for the message you actually clicked, and if that fails too it says the message could not be loaded rather than quietly showing you something that looks like the real thing.
  • "View Source" shows the message you are looking at. The raw source was read straight out of the stored copy filed under that number, with nothing checking it was the right message — so after a change of mail host it could hand over another message's headers and body under the header of the one on screen. The source is now checked against the message it claims to be, and MailVault says so plainly instead of showing the wrong one.
  • A backup no longer undoes MailVault's own repair of your archive. When a mail server reissues its message numbers, MailVault repairs the archive on this computer: mail the server still has is refiled under its new number, and mail it does not have is set aside — kept on disk, never deleted. The next backup then copied those set-aside messages back off the backup drive into the archive, under the numbers they used to have, undoing the repair. Every backup did it again, and nothing showed that it had happened. Messages the repair set aside now stay set aside, while a copy it never ruled out still comes back from the backup drive as before. An archive that was already affected keeps its wrong copies until the next repair runs.
  • A bulk archive or delete now says what it is doing to a screen reader. Moving thousands of messages off a server reported its progress in a bar and nowhere else, so with a screen reader on, the longest and least reversible operation in MailVault ran in silence. Bulk save, bulk operations and the selection bar now announce the phase, each quarter of the way through, and how it ended — including how many failed — without reading out every percent for the length of the run.
  • A narrow window no longer pushes the message out of sight. Below 768px wide the list and the message stack one above the other, and the height of the list came from the same setting as its width in the three-column layout. Widen the list with the divider, then make the window narrow — half a screen, or the smallest size MailVault opens at — and that width became a height taller than the window: the message you clicked was rendered below the bottom edge, along with the divider that would have brought it back, so clicking a message showed nothing and there was no way to undo it from inside the app. The two layouts now keep their own sizes, neither can be dragged past what the window can hold, and the stacked layout gives the whole window to the list until you open something — instead of holding half of it for a pane that says "Select an email to read".
  • Settings stops hiding its own tabs in a narrow window. In General and in Backup & Restore, the row of tabs ran off the right-hand edge — "Notifications" and "Keyboard Shortcuts" were simply not on screen, in a strip that scrolled sideways with nothing to show that it could. The tabs now wrap onto a second line, and the settings list on the left takes less room when the window is small.
  • A narrow message list keeps more of the subject. The sender column was a fixed width whatever the list was doing, so in a half-screen window it took nearly as much room as the subject beside it. It is now a share of the row: unchanged at the widths it has always had, and it gives way first when the list is narrow, because a subject is what a list is read for.
  • The layout picker says when three columns will not fit. Choosing "Three Columns" in a window too narrow to hold them did nothing at all, with nothing to explain why. Settings → General → Layout now says the panes are stacked until the window is widened, and that the choice is remembered.
  • "Subject:" fits its label in the compose window. The label was five pixels narrower than the word.
v2.10.2 August 25, 2026

Added

  • A message you are writing is saved to Drafts as you type. Until now a half-written message existed only in the window it was being typed in, so anything that closed that window took the text with it. Three tenths of a second after you stop typing, the message is now written to the Drafts folder of the account it will be sent from, on this computer — recipients, subject, body and attachments — and it shows up in that folder like any other message. It is one draft, not one per pause: each save replaces the last. Change the From address to another account and the draft moves to that account's Drafts. Send the message, or discard it, and the draft goes away with it. A message with no recipient yet is saved too — that is the point. Nothing is uploaded to the mail server yet; this is the local copy only.
  • A draft in the Drafts folder opens back up for writing. A message saved as you typed could be read back but not continued: clicking its row opened it in the reading pane, like any other message, and the only way to carry on was to start again. Clicking a draft you wrote now reopens it in a message window — recipients, subject, body and attachments as you left them, sent from the account it belongs to — and carrying on updates that same draft instead of leaving the half-written one behind. A reply you had started keeps its place in the conversation. Mail archived from a server is unaffected: it still opens in the reading pane.
  • A link to the other apps from the same maker. Help → "More Apps by GraphicMeat", and a matching row in Settings → Help & Support, open graphicmeat.com.

Fixed

  • A search result opens the message you searched for, not another one on the same number. Search looks across every folder, but a result carried no record of which folder it came from — so opening one went looking in the folder the sidebar happened to have selected. Two things followed. If that folder held a message with the same internal number, that message opened instead, under the header of the one you clicked. If it did not, the message would not open at all and MailVault reported it as no longer on the server. Results now carry their own folder, and two messages that share a number in different folders stay two separate results.
  • Selecting text in a message you are writing no longer folds it away — or loses it. Sweeping a selection past the edge of the compose window counted as clicking away from the window: the message collapsed into a draft bubble. Opening the bubble and doing it again was worse, because a message brought back from a bubble was treated as untouched — so that second time it closed for good, with no "Discard message?" prompt, and everything typed was gone. A selection that begins inside the window is now only a selection; clicking away still minimizes, but only when the click both starts and ends outside. A message restored from a bubble is unsaved work again: clicking away minimizes it, and Close asks first.
  • A search across "all folders" now really searches every folder on the server. The results header said all folders, but a search of the server only ever looked in the Inbox — so a message sitting in any other folder came back as a message that does not exist, which is exactly the check people make when a backup looks smaller than the mailbox it came from. The search now walks every folder the account has, Inbox first, filling the results in as it goes and showing which folder it is on, so a sweep of sixty folders no longer reads as a search that found nothing. A folder that refuses to open is skipped instead of ending the search, retyping the query abandons the old sweep, and the folder picker now lists folders nested inside other folders, which were unselectable before.
  • Help → "MailVault Website" opens the site that is actually there. The menu item, and the two update dialogs that name the website, pointed at mailvault.app, which is offline. All three now open mailvaultapp.com. The same link is in Settings → Help & Support, where Windows and Linux can reach it too.

It now loads just the embedded images from the message's local copy when you open it.
  • The message list header now says how much of the mailbox is actually in the list. It always showed the mailbox's total on the server, so a list that was still filling looked exactly like a finished one. It now reads "741 of 15,067 emails" until everything is loaded.
  • Adding an account with a non-standard mail-server port works again. Typing anything into the IMAP or SMTP port field made the connection test fail before it dialled — the port was sent as text where a number was expected — so only accounts on the default ports could be added.
  • Bulk operations can now select the whole mailbox, not just what's on screen. Picking "All" in Bulk Email Operations only covered the messages the list had scrolled in so far — on a 15,000-message inbox that was a few hundred — even though the app already held every message locally. It now selects from the full local copy of the mailbox, and skips messages you have already deleted.
  • Switching back to an account is instant now. The message list restarted at “500 of 15,065” and counted up again on every switch, because the app rebuilt the list by reading one file per message off disk — fifteen thousand of them — even though it had just had them all in memory. It now keeps the last few mailboxes it showed you, and when mail has arrived while you were away it re-reads only the messages that actually changed rather than starting the whole list over.
  • Loading a large mailbox no longer crawls. Filling the list read every message file in the mailbox over again on each step — fifteen thousand of them, several times a second — so the count climbed a little at a time with long pauses and looked stuck. It now reads only the messages it doesn't already have.
  • The message list no longer stops partway through loading and sits there. After switching accounts it could stick at a few hundred messages — spinner showing, nothing actually downloading — until you hit refresh. Two parts of the load raced over the same "still loading" flag, and the quick server check added in this release made the wrong one win.
  • The email counter no longer counts backwards. The “x / y emails” indicator measured how much of the list was on screen, which drops every time you switch accounts, so a switch looked like a fresh download. It now shows how much of the mailbox has been downloaded — a number that only goes up — and stops spinning when nothing is actually downloading.
  • Switching accounts no longer restarts the whole load. Every switch ran a full server sync and waited on it, even for an account you had opened moments earlier, and it restarted the background download of every other account's mail from the beginning. The app now asks the server whether anything actually changed — one quick check instead of a full sync — and picks up background work where it left off rather than starting over.
  • A backup that succeeded is no longer reported as failed. The prompt shown after a backup finishes could error and drag the completed backup down with it, marking it failed and quietly re-running it up to three more times.
  • A dropped connection can no longer wipe cached mail. If the server closed the connection while listing a mailbox's messages, the list came back empty with no error — and the empty list was treated as "everything was deleted". The listing is now checked against the server's own message count and refuses to report a partial result.
  • Changing only the port of an account's mail server no longer reuses the old connection. Connections were pooled by address alone, so a config that differed only by port was handed a connection to the previous server.
  • Large mailboxes no longer get stuck loading forever on some servers. Listing the messages in a mailbox used one very long server reply, and on a 15,000-message mailbox some servers (Purelymail among them) interrupt that reply with a keep-alive line, which made it unreadable. The listing now arrives one message per line, so an interruption can't corrupt it.
  • A failed lookup can no longer blank your cached mail. When that reply failed to parse, the leftovers stayed in the connection and the next command read the wrong answer — reporting an empty mailbox and deleting hundreds of cached messages. Connections are now dropped after a failed command instead of being reused.
  • A mailbox whose background fill fails now loads normally instead of spinning. The app waits while the helper fills a partly cached mailbox; if that fill failed, the wait never ended and the list kept loading with nothing actually downloading. The app now falls back to loading pages itself.
  • Mail connections are closed properly when you quit. The app and the background helper now log out of every open server connection on exit, instead of leaving them for the server to time out.
  • Email light/dark switching works again in installed builds. The app's security policy was tightened at build time in a way that blocked the script that darkens email content, so the Light/Dark button and the email theme setting did nothing — the button changed state, the email stayed light. Opening the same email in its own window was unaffected, which is why it looked intermittent.
  • A mailbox that is only partly cached now fills itself in, once. After a restore or a server migration the local cache could hold a few hundred messages of a 15,000-message mailbox while still looking fully in sync — so every launch dragged the missing thousands off the server, a few hundred at a time, and rarely got to the end before the app was closed. The background helper now notices the shortfall and downloads only the missing headers, newest first, while you keep using the app.
  • Loading a large mailbox no longer slows down the further it gets. Each batch of messages used to re-save every message loaded so far, so a full 15,000-message load performed well over half a million file writes. Only the new batch is written now.
  • Your other accounts no longer re-download their whole mailbox at startup. Background loading for non-active accounts (and the Sent folder of the active one) fetched every page from the server on every launch, ignoring the cache entirely. It now syncs the same incremental way the active mailbox does.
  • The background helper is reachable again. The app was looking for the helper's connection socket in the wrong folder, so every request to it failed and Settings always reported "Helper Not Running" — even while the helper was running normally. Affected contact indexing, AI classification, snapshots and background sync since 2.7.0.
  • App restarts no longer re-download the mailbox. Saving headers used to delete every cached message that wasn't in the on-screen window, so an ordinary save cut a 14,000-message cache down to 500 — and the rest was then re-fetched from the server page by page, roughly 70 IMAP round-trips on every launch. The cache is now treated as a superset of the loaded window and only drops messages that are actually gone.
  • Read, unread and star changes now survive a restart. Header cache writes skipped files that already existed, so a flag change updated the list but never reached disk and the old state came back on the next launch.
  • Background sync now fetches only what changed — the messages that arrived since the last sync, plus flag updates — instead of re-fetching the newest 500 headers every time. Sync metadata is also no longer wiped by routine cache saves, which had been silently forcing that full fetch.
  • Scrolling back through a large mailbox now reads from the local cache instead of re-fetching pages from the server.
  • Deleted emails are pruned from the local cache on a count mismatch and, as a backstop, on a periodic full reconciliation — so a message deleted from another device can no longer linger in the list.
  • Messages the server has flagged as deleted but not yet removed are now hidden from the list. Messages archived to your local vault stay visible either way.
  • Emails no longer reappear as duplicates or ghosts after a server rebuilds its message IDs (UIDVALIDITY change) — the stale generation is now cleared instead of merged with the new one.
  • Read and star state now refreshes on servers that don't support CONDSTORE, which previously left cached messages showing stale flags indefinitely.
  • Deletions made in Outlook/Microsoft 365 accounts are now removed from the local cache instead of reappearing on the next load.
  • The Sent folder for Outlook/Microsoft 365 accounts is no longer capped at 200 messages.
  • Loading more messages could skip about 100 emails when the list was seeded from the cache; pages now overlap and de-duplicate instead.

Internal

  • Removed a second, unused email cache implementation (mailvault_core::cache) and the 14 daemon RPCs that fronted it — nothing called them, and the app has always read the sidecar cache through Tauri.
  • A failed background sync no longer leaks its IMAP connection back into the pool.
