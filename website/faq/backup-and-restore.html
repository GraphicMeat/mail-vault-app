Backup and Restore

How MailVault archives mail, what archiving then deleting does to the server copy, when automatic backups run, and how to export and re-import your vault.

How does MailVault back up emails?

MailVault connects to your email server using the IMAP protocol and downloads each email as a standard .eml file stored in Maildir format on your Mac or Linux machine. Each email is one file on disk — human-readable, portable, and compatible with any mail client. Once a message is in your vault you can delete the server copy to free up space; the local one is unaffected.

What happens when I archive an email?

Archiving downloads the full email from your server (if not already cached) and stores it as a .eml file on disk with the A (Archived) flag in the filename. If the email was already cached locally, MailVault simply renames the file to add the archive flag. Archived emails appear under the Vault view and are included in backups. The server copy is untouched until you delete it yourself.

What happens when I archive and delete from server?

Archive & Delete runs three steps in order: it copies the message into your vault as an .eml file, checks that the copy is really there, and only then deletes it from the server. Anything that fails the check stays on the server — a failed copy never costs you the original. Afterwards the row shows your only copy: the vault is the one place that message still exists, which is also the cue to keep a backup drive attached.

What happens if I delete emails from the server?

Anything you archived first stays in your vault, untouched by what the server does afterwards — that is the whole point of the product. Anything you did not archive is gone with the server copy, so MailVault shows the state of every message on its own row before you delete: on the server, in your vault, or both. The safe route is Archive & Delete, which copies each message into your vault and verifies it there before removing it from the server.

How does backup and restore work?

MailVault exports your emails as a ZIP archive containing all .eml files plus a manifest.json that maps emails to accounts by email address (not internal IDs), making backups portable across different installations. You can choose to export all emails or archived only. Importing is idempotent — if an email already exists locally, it won't be duplicated. If a backup contains emails for an account you haven't set up yet, MailVault creates it automatically (you just re-enter the password in Settings).

Can I choose the hours automatic backups run?

Yes, with Premium. Settings → Backup & Restore → Backup Schedule offers four frequencies: every hour, once a day, once a week, and At set hours. Choose At set hours and a grid of all 24 hours appears; tap the ones you want, say 07, 12 and 22, and MailVault backs up on the hour at each of them and never in between. Every frequency runs only while the app is idle, so a backup never starts under your hands.

Set hours are meant for a vault or backup mirror on an external drive that something else already uses on its own schedule, Time Machine most often: pick the hours that drive is free. A selected hour that comes round while MailVault is busy is skipped rather than caught up later, so the next selected hour is the next attempt.
