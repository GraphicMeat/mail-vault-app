Fehlerbehebung

Fixes for the problems people hit most: the Gmail daily bandwidth cap, spellcheck underlining nothing on Linux, and a folder added on the server not showing up yet.

Was sind die Bandbreitenlimits von Gmail, und was passiert, wenn ein Backup sie erreicht?

Google begrenzt, wie viele Mail-Daten ein einzelnes Gmail- oder Google-Workspace-Konto pro Tag bewegen kann. Die Grenzen gelten für das Konto, nicht für die App — Apple Mail, dein Handy und MailVault schöpfen alle aus demselben Tagesbudget.

Zugriffsmethode Download-Limit Upload-Limit
IMAP (was MailVault nutzt) 2500 MB / Tag 500 MB / Tag
POP 1250 MB / Tag —
Gmail-Weboberfläche 750 MB / Stunde, 1250 MB / Tag 300 MB / Stunde, 1500 MB / Tag

Überschreitest du ein Limit, sperrt Google das Konto vorübergehend: meist etwa 1 Stunde, es kann aber bis zu 24 Stunden dauern. Die Limits sind in jeder Google-Workspace-Edition gleich, und Google kann sie ohne Ankündigung ändern — die aktuellen Zahlen stehen in Googles Dokumentation zu den Bandbreitenlimits.

Was das für ein erstes Backup heißt. Ein Postfach, das größer als etwa 2,5 GB ist, lässt sich per IMAP nicht an einem Tag herunterladen — kein Client schafft das, das ist eine Grenze auf Serverseite. Rechne bei einem großen Archiv mit mehreren Tagen.

Was MailVault tut. Es erkennt die Limit-Antwort, beendet den Lauf sauber, statt sich in eine längere Sperre hineinzuwiederholen, und sagt dir, dass das Tageslimit erreicht wurde. Starte das Backup erneut, sobald die Sperre vorbei ist, und es macht dort weiter, wo es aufgehört hat — schon lokal gespeicherte Nachrichten werden übersprungen, nichts wird zweimal geladen. Alles, was bereits auf der Festplatte liegt, bleibt währenddessen lesbar und durchsuchbar.

Warum unterstreicht die Rechtschreibprüfung unter Linux nichts?

Weil auf dem Rechner kein Wörterbuch liegt. macOS und Windows liefern eines mit dem System mit; unter Linux kommt das Wörterbuch von deiner Distribution, und eine minimale Desktop-Installation hat oft keines. MailVault prüft die Rechtschreibung über WebKitGTK, das Wörter über enchant und hunspell nachschlägt — es kann also erst unterstreichen, wenn ein hunspell-Wörterbuch installiert ist.

Der Button in der Nachrichten-Werkzeugleiste sagt dir, in welchem Fall du bist. Ist ein Wörterbuch vorhanden, schaltet er die Unterringelungen an und aus, und MailVault merkt sich die Einstellung. Ist keines da, öffnet er stattdessen genau diese Anleitung, statt einen Schalter vorzutäuschen.

Installiere ein Wörterbuch für deine Sprache:

Debian, Ubuntu, Mint
sudo apt install hunspell-en-us
Fedora
sudo dnf install hunspell-en
Arch, Manjaro
sudo pacman -S hunspell-en_us
openSUSE
sudo zypper install myspell-en_US

Ersetze den Sprachcode durch deinen eigenen — hunspell-de-de, hunspell-fr und so weiter. Du kannst mehrere installieren; MailVault prüft gegen das, das zu deiner Systemsprache passt, und gegen alle, wenn keines passt. Starte MailVault danach neu — die Prüfung wird beim Start der App eingerichtet.

Der Snap-Build ist ein Sonderfall. Ein streng abgeschottetes Snap sieht die auf dem Host installierten Wörterbücher nicht und bringt deshalb eine eigene Kopie mit. Meldet das Snap, dass kein Wörterbuch da ist, installiere stattdessen das .deb-Paket — es nutzt die Wörterbücher, die schon auf deinem System liegen.

I added a folder on the server — how soon does MailVault show it?

Within ten minutes. MailVault keeps a copy of your folder list on disk so the sidebar fills in the moment you open an account, and it re-reads the list from the server at most once every ten minutes. Create, rename or delete a folder in webmail or another mail client, and MailVault picks the change up the next time it opens that account or you click a folder in the sidebar — once those ten minutes have passed.

Restarting does not hurry it along. The cached list is on disk, not in memory, so it survives a quit and relaunch. Waiting out the ten minutes and then clicking any folder is the fastest way to see a change you just made.

The Refresh button is about messages, not folders. It reloads the mail in the folder you are reading. The folder list runs on its own ten-minute check, which is why a brand new folder can stay hidden for a few minutes after a refresh.

Subfolders need no setup. MailVault builds the tree from the paths the server reports, so a new subfolder turns up nested under its parent with the right name and position. Accounts you are not currently reading are refreshed in the background on the same schedule, a couple at a time, so switching to one rarely shows you a stale list.
