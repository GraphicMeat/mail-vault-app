How Does SMTP Work?

SMTP stands for Simple Mail Transfer Protocol. It carries outgoing email from an app to a submission server and between mail servers on the way to the recipient.

On this page
  • From your app to your provider
  • Between mail servers
  • How the recipient reads the message
  • Related reading
  • Protocol references

Reviewed on November 28, 2026.

From your app to your provider

When you press Send in an app configured for SMTP, the app usually signs in to your provider’s submission server and hands over the message and its delivery addresses. Port 587 commonly uses STARTTLS to upgrade the connection to TLS. Port 465 starts with TLS from the first byte. Use the settings your provider specifies.

Between mail servers

For delivery to another domain, the sending server looks up that domain’s mail servers in DNS. It typically relays the message over port 25. If delivery fails temporarily, the sender’s server can queue the message and retry. A permanent failure can generate a bounce message.

How the recipient reads the message

The receiving system can filter the message before placing it in a mailbox. The recipient then opens it through webmail, syncs it with IMAP, or retrieves it with POP3 if their provider offers that option.
