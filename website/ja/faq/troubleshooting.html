トラブルシューティング

よくある2つの問題の対処法。Gmailの1日あたりの通信量の上限と、Linuxでスペルチェックが何も下線を引かない件。

Gmailの帯域制限とは何ですか。バックアップが上限に達するとどうなりますか？

Googleは、1つのGmailまたはGoogle Workspaceのアカウントが1日に転送できるメールデータの量に上限を設けています。上限はアプリではなくアカウントに対するものなので、Apple Mail、スマートフォン、MailVaultはすべて同じ1日分の枠を使います。

アクセス方法 ダウンロードの上限 アップロードの上限
IMAP （MailVaultが使用） 2500 MB / 日 500 MB / 日
POP 1250 MB / 日 —
Gmailのウェブクライアント 750 MB / 時、1250 MB / 日 300 MB / 時、1500 MB / 日

上限を超えるとGoogleはアカウントを一時的に停止します。通常は1時間ほどですが、24時間続くこともあります。上限はどのGoogle Workspaceのエディションでも同じで、Googleは予告なく変更できます — 現在の数値はGoogleの帯域制限のドキュメントをご覧ください。

最初のバックアップにとって、これが何を意味するか。およそ2.5 GBを超えるメールボックスは、IMAPで1日のうちにダウンロードしきれません — どのクライアントでも無理で、これはサーバー側の上限です。大きなアーカイブには数日かかると見込んでください。

MailVaultの振る舞い。上限に達した応答を認識し、より長い締め出しを招く再試行はせずに実行をきれいに停止して、1日の上限に達したことをお知らせします。停止が解けてからバックアップを始め直せば、止まったところから続きます — すでにローカルに保存されたメッセージは飛ばされるので、二度ダウンロードされることはありません。待っている間も、ディスクにあるものはすべて読めますし、検索もできます。

Linuxでスペルチェックの下線が表示されないのはなぜですか？

そのマシンにスペル辞書がないからです。macOSとWindowsはシステムに辞書が同梱されていますが、Linuxでは辞書はディストリビューションから提供され、最小構成のデスクトップにはないことがよくあります。MailVaultはWebKitGTKを通じてスペルチェックを行い、WebKitGTKはenchantとhunspellを使って単語を調べます。そのため、hunspellの辞書が入っていないと下線を引けません。

どちらの状態にいるかは、メッセージのツールバーのボタンが教えてくれます。辞書があれば、下線の表示をオンとオフに切り替え、その設定をMailVaultが覚えます。辞書がなければ、スイッチのふりをする代わりに、この説明そのものを開きます。

お使いの言語の辞書をインストールしてください:

Debian、Ubuntu、Mint
sudo apt install hunspell-en-us
Fedora
sudo dnf install hunspell-en
Arch、Manjaro
sudo pacman -S hunspell-en_us
openSUSE
sudo zypper install myspell-en_US

言語のコードはご自分のものに置き換えてください — hunspell-de-de、hunspell-frなどです。複数を入れてもかまいません。MailVaultはシステムの言語に合うものを使って確認し、合うものがなければすべてを使って確認します。そのあとMailVaultを再起動してください — スペルチェックはアプリの起動時に設定されます。

snapのビルドは特別な場合です。厳密に閉じ込められたsnapはホストに入れた辞書を見られないため、自前のコピーを持っています。snapが辞書なしと伝えてきたら、代わりに.debパッケージを入れてください — こちらはシステムにすでにある辞書を使います。
