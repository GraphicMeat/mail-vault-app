Questions fréquentes

Tout ce qu'il faut savoir sur MailVault.

MailVault est un client e-mail de bureau gratuit et open source pour macOS et Linux qui conserve vos e-mails dans un coffre sur votre propre disque. Il se connecte à vos comptes e-mail en IMAP et enregistre tous les messages sous forme de fichiers .eml standard (RFC 5322) au format Maildir sur votre ordinateur, ce qui vous donne une sauvegarde hors ligne permanente, sans dépendance à un éditeur.

MailVault se connecte à votre serveur de messagerie avec le protocole IMAP et télécharge chaque e-mail sous forme de fichier .eml standard, au format Maildir, sur votre Mac ou votre machine Linux. Chaque e-mail est un fichier sur le disque — lisible par un humain, portable, et compatible avec n'importe quel client de messagerie. Une fois un message dans votre coffre, vous pouvez supprimer la copie du serveur pour libérer de l'espace ; la copie locale n'est pas touchée.

MailVault fonctionne avec tout fournisseur d'e-mail qui prend en charge IMAP, dont Gmail, Outlook, Yahoo Mail, iCloud Mail, ProtonMail (avec Bridge), Fastmail, Zoho Mail, ainsi que tout fournisseur auto-hébergé ou professionnel offrant un accès IMAP.

MailVault est gratuit pour ses fonctions essentielles : lecture, rédaction, recherche, fils de discussion, archivage local et sauvegarde manuelle. Les fonctionnalités Premium — sauvegardes automatiques programmées, migration de boîte entre comptes et règles de nettoyage automatique — sont disponibles pour $4/mois ou $25/an ; la formule annuelle comprend 14 jours d'essai gratuit. Le code source est disponible sur GitHub. Voir les tarifs complets pour le détail.

Votre coffre est un dossier de fichiers .eml standard organisés au format Maildir sur votre Mac ou votre machine Linux — un fichier par e-mail, aucune base de données requise. Vos données ne quittent jamais votre ordinateur et ne sont jamais envoyées vers un service cloud. Comme .eml est un standard universel, vos e-mails peuvent être ouverts par Apple Mail, Thunderbird, Outlook ou n'importe quel autre client de messagerie — vous n'êtes jamais captif de MailVault.

Structure des dossiers :

~/Library/Application Support/com.mailvault.app/
└── maildir/
    └── you@example.com/
        └── INBOX/
            ├── headers.json          ← cached list for fast loading
            └── cur/
                ├── 1234567890.eml    ← auto-cached email
                └── 1234567891_AS.eml ← archived + seen email

.eml (RFC 5322) est le format standard d'Internet pour les messages électroniques. Chaque e-mail — en-têtes, corps et pièces jointes — est stocké dans un seul fichier texte autonome. Contrairement aux bases de données propriétaires, les fichiers .eml s'ouvrent dans n'importe quel client de messagerie (Apple Mail, Thunderbird, Outlook) et se lisent dans n'importe quel éditeur de texte.

Maildir est une structure de dossiers éprouvée pour stocker du courrier, utilisée par les serveurs de messagerie depuis des décennies. Chaque e-mail est un fichier : il n'y a donc pas de base de données unique qui puisse se corrompre — si un fichier est endommagé, le reste de votre archive n'est pas touché. Ensemble, .eml + Maildir garantissent que vos e-mails restent lisibles dans le temps, portables, et jamais captifs d'une seule application.

Indicateurs dans le nom de fichier :

MailVault ajoute des caractères d'indicateur au nom du fichier .eml pour en suivre l'état : A = Archivé, S = Lu (Seen), R = Répondu, F = Marqué. Par exemple, 1234567890_AS.eml signifie que l'e-mail a été archivé et lu.

MailVault est conçu avec la confidentialité comme priorité. Vos identifiants de messagerie sont stockés dans le trousseau macOS ou dans le Secret Service de Linux, jamais dans un fichier en clair. Toutes les données restent sur votre machine — pas de synchronisation cloud, pas de pistage, pas de statistiques, pas d'exploitation de données. L'application est open source, vous pouvez donc vérifier le code vous-même.

Tout ce que vous avez archivé au préalable reste dans votre coffre, indépendamment de ce que fait le serveur ensuite — c'est toute la raison d'être du produit. Tout ce que vous n'avez pas archivé disparaît avec la copie du serveur : MailVault indique donc l'état de chaque message sur sa propre ligne avant que vous ne supprimiez — sur le serveur, dans votre coffre, ou les deux. La voie sûre est Archiver & Supprimer, qui copie chaque message dans votre coffre et l'y vérifie avant de le retirer du serveur.

Il existe un problème connu côté serveur chez Microsoft qui touche les comptes personnels Outlook.com, Hotmail et Live.com depuis la fin 2024. Après la connexion avec votre compte Microsoft, la connexion IMAP échoue avec « User is authenticated but not connected ». Cela concerne tous les clients de messagerie tiers qui utilisent IMAP avec OAuth2, pas seulement MailVault.

Microsoft impose OAuth2 pour les comptes personnels. Malheureusement, leur service IMAP souffre d'une régression qui empêche les sessions authentifiées par OAuth2 de se connecter à la boîte mail.

Ce que vous pouvez faire :

  • Les comptes Microsoft 365 Business/Enterprise ne sont pas touchés — OAuth2 fonctionne normalement pour les comptes d'organisation
  • Suivre le problème — c'est un problème côté serveur que seul Microsoft peut corriger. Le fil Microsoft Q&A en assure le suivi
  • Utiliser Outlook sur le web ou les applications officielles de Microsoft en attendant, pour les comptes personnels
  • MailVault est prêt — dès que Microsoft aura réglé le problème, la connexion OAuth2 de MailVault fonctionnera immédiatement, sans aucune modification

Pour le détail technique : MailVault utilise la même implémentation d'OAuth2 que Mozilla Thunderbird, en suivant la documentation officielle de Microsoft sur OAuth2 pour IMAP, avec authentification PKCE et XOAUTH2.

Proton Mail chiffre votre courrier de bout en bout : il n'expose donc pas IMAP directement. Le connecter à MailVault (ou à n'importe quel client de messagerie tiers) demande Proton Mail Bridge — une application de bureau signée Proton, qui tourne sur votre propre ordinateur et expose votre boîte chiffrée en IMAP/SMTP standard sur 127.0.0.1. Bridge exige une formule Proton Mail payante ; il n'est pas disponible sur l'offre gratuite de Proton.

Étapes de configuration :

  1. Installez Proton Mail Bridge depuis le site de Proton
  2. Connectez-vous à Bridge avec votre compte Proton
  3. Bridge affiche des identifiants IMAP/SMTP par compte — le mot de passe indiqué est un mot de passe d'application généré par Bridge, et non le mot de passe habituel de votre compte Proton
  4. Dans MailVault, choisissez Proton Mail Bridge dans la liste des fournisseurs (ou IMAP personnalisé s'il n'y figure pas) et saisissez :
    • Serveur : 127.0.0.1
    • Port IMAP : 1143, sécurité : STARTTLS
    • Port SMTP : 1025
    • Nom d'utilisateur : votre adresse e-mail Proton
    • Mot de passe : le mot de passe généré par Bridge à l'étape 3

Proton Mail Bridge doit tourner en arrière-plan chaque fois que MailVault se synchronise — si Bridge est fermé, MailVault ne peut pas atteindre la boîte mail. Le courrier que vous avez déjà archivé reste entièrement lisible et consultable dans MailVault même quand Bridge est fermé, puisque MailVault fonctionne d'abord en local et lit son propre stock de fichiers .eml plutôt que Bridge en direct.

Bridge protège son serveur IMAP/SMTP local avec un certificat TLS auto-signé. MailVault s'en occupe automatiquement pour les connexions locales (127.0.0.1) : aucune installation manuelle de certificat n'est nécessaire.

C'est courant chez Fastmail et chez tout fournisseur où l'adresse avec laquelle vous vous connectez n'est pas celle que vous communiquez.

Seule l'adresse From du courrier sortant change. Vos nom d'utilisateur et mot de passe restent exactement les mêmes, MailVault se connecte toujours en IMAP et en SMTP avec le compte que vous avez configuré, et aucun en-tête Reply-To n'est ajouté — les réponses partent vers l'adresse depuis laquelle vous envoyez.

Trouver et vérifier l'adresse :

  • Suggestions — MailVault propose les adresses qu'il a déjà vues dans votre propre courrier : celles depuis lesquelles vous avez déjà envoyé, et celles sur lesquelles arrive le courrier qui vous est adressé.
  • Vérifier — envoie un seul message de test depuis l'adresse, vers votre propre boîte par défaut, pour que vous puissiez confirmer que votre fournisseur l'accepte avant d'en dépendre.
  • En cas de refus — l'adresse doit être un alias ou une identité que votre fournisseur autorise cet identifiant à utiliser. Fastmail accepte n'importe quel alias du compte ; Gmail exige que l'adresse soit ajoutée sous « Envoyer des e-mails en tant que » dans les paramètres Gmail, et Microsoft 365 exige l'autorisation Send As d'un administrateur.

Les alias se configurent chez votre fournisseur d'e-mail, pas dans MailVault — MailVault envoie depuis une adresse que votre fournisseur a déjà autorisée.

MailVault demande macOS 11 (Big Sur) ou plus récent, et tourne nativement sur Intel comme sur Apple Silicon. Sous Linux, il est distribué en .deb, AppImage, Snap et Flatpak pour Ubuntu 22.04+ / Debian 12+. Il reste dans la barre de menus et continue de synchroniser fenêtre fermée.

Les pièces jointes sont intégrées à chaque fichier .eml sous forme de parties MIME — elles ne sont pas stockées dans des fichiers séparés. Quand vous ouvrez un e-mail, le moteur Rust de MailVault analyse la structure MIME et en extrait les pièces jointes à la volée. Vous pouvez Ouvrir, Enregistrer sous ou Afficher dans le dossier n'importe quelle pièce jointe directement depuis le lecteur d'e-mail. Les pièces jointes extraites sont mises en cache temporairement, pour être rouvertes rapidement.

L'archivage télécharge l'e-mail complet depuis votre serveur (s'il n'est pas déjà en cache) et l'enregistre en fichier .eml sur le disque, avec l'indicateur A (Archivé) dans le nom du fichier. Si l'e-mail était déjà en cache en local, MailVault se contente de renommer le fichier pour y ajouter l'indicateur d'archivage. Les e-mails archivés apparaissent dans la vue Coffre et sont inclus dans les sauvegardes. La copie sur le serveur reste intacte tant que vous ne la supprimez pas vous-même.

Archiver & Supprimer exécute trois étapes dans l'ordre : il copie le message dans votre coffre en fichier .eml, vérifie que la copie est bien là, et seulement ensuite le supprime du serveur. Tout ce qui échoue à la vérification reste sur le serveur — une copie ratée ne vous coûte jamais l'original. Ensuite, la ligne affiche seule copie : le coffre est le seul endroit où ce message existe encore, ce qui est aussi le signal qu'il faut garder un disque de sauvegarde branché.

MailVault exporte vos e-mails dans une archive ZIP contenant tous les fichiers .eml, ainsi qu'un manifest.json qui rattache les e-mails aux comptes par adresse e-mail, et non par identifiant interne, ce qui rend les sauvegardes portables d'une installation à l'autre. Vous pouvez exporter tous les e-mails ou seulement les archivés. L'import est idempotent — si un e-mail existe déjà en local, il n'est pas dupliqué. Si une sauvegarde contient des e-mails pour un compte que vous n'avez pas encore configuré, MailVault le crée automatiquement (vous n'avez qu'à ressaisir le mot de passe dans les Paramètres).

Google plafonne le volume de courrier qu'un compte Gmail ou Google Workspace peut transférer par jour. Ces plafonds s'appliquent au compte, pas à l'application — Apple Mail, votre téléphone et MailVault puisent tous dans le même budget quotidien.

Méthode d'accès Limite de téléchargement Limite d'envoi
IMAP (ce que MailVault utilise) 2500 Mo / jour 500 Mo / jour
POP 1250 Mo / jour —
Client web Gmail 750 Mo / heure, 1250 Mo / jour 300 Mo / heure, 1500 Mo / jour

Dépassez une limite et Google suspend temporairement le compte : en général une heure environ, mais cela peut durer jusqu'à 24 heures. Les limites sont les mêmes sur toutes les éditions de Google Workspace, et Google peut les modifier sans préavis — voir la documentation de Google sur les limites de bande passante pour les chiffres à jour.

Ce que cela implique pour une première sauvegarde. Une boîte mail de plus de 2,5 Go environ ne peut pas être téléchargée en une journée par IMAP — aucun client n'en est capable, c'est un plafond côté serveur. Comptez plusieurs jours pour une grosse archive.

Ce que fait MailVault. Il reconnaît la réponse de limite, arrête proprement l'exécution au lieu de réessayer et de provoquer un blocage plus long, et vous indique que la limite quotidienne a été atteinte. Relancez la sauvegarde une fois la suspension levée : elle repart là où elle s'était arrêtée — les messages déjà enregistrés en local sont ignorés, rien n'est donc téléchargé deux fois. Tout ce qui est déjà sur le disque reste lisible et consultable pendant l'attente.

MailVault garde toujours une copie de travail de votre courrier dans son propre espace de stockage — c'est elle que vous lisez, fouillez et ouvrez. Un emplacement de sauvegarde externe ajoute une seconde copie, indépendante, sur un support que vous maîtrisez : un SSD externe, un partage NAS ou un dossier synchronisé.

  • Écrite en même temps que la copie de travail. Pendant une sauvegarde, chaque message est enregistré aux deux endroits, dans la même disposition .eml + Maildir — la seconde copie s'ouvre donc dans Apple Mail, Thunderbird ou n'importe quel autre client, sans MailVault.
  • Un stockage froid, pas un miroir. L'application ne le lit jamais au quotidien. Les e-mails supprimés sur le serveur, ou retirés depuis MailVault, restent dans la copie externe.
  • Les indicateurs de lecture et d'écriture survivent dans les deux sens. Les copies sont réconciliées avant chaque exécution : un message que vous avez lu reste lu.
  • Indépendante de l'application. Si cet ordinateur meurt ou si vous désinstallez MailVault, le dossier externe reste une archive de courrier complète, qui se décrit elle-même.

Réglez cela dans Paramètres → Sauvegarde → « Seconde copie — stockage froid externe » et choisissez le dossier que vous voulez. Sur macOS, MailVault enregistre un signet à portée de sécurité pour ce dossier : l'accès survit donc aux redémarrages et aux mises à jour de l'application — un simple chemin ne le ferait pas. Un badge d'état affiche Prêt, Réautorisation nécessaire, Indisponible ou Accès refusé, et la réautorisation se fait en un clic.

Si le support est débranché en cours de sauvegarde, la copie de travail va tout de même au bout et MailVault indique combien de messages n'ont pas atteint la copie externe. L'exécution suivante les recopie — rien n'est perdu, et l'échec n'est jamais silencieux.

Oui. Par défaut, MailVault garde son stockage de courrier dans son propre dossier Application Support, sur votre disque de démarrage. Vous pouvez déplacer ce stockage vers n'importe quel dossier sur n'importe quel support — un SSD externe, un second disque interne — ce qui compte dès qu'une archive atteint des dizaines de gigaoctets.

Seules les données de courrier bougent : les messages, les caches d'en-têtes, le cache des pièces jointes et les listes de dossiers. Les comptes, les réglages et les journaux restent dans le dossier propre à l'application, de sorte que MailVault peut toujours démarrer assez loin pour vous signaler qu'un disque manque et vous redemander le dossier.

Le déplacement est vérifié avant la moindre suppression. MailVault copie tout vers le nouveau dossier, contrôle que chaque fichier est bien arrivé à la bonne taille, bascule, et seulement ensuite retire les originaux. Un déplacement interrompu par une déconnexion ou un plantage laisse le stock actuel intact ; relancez-le et il reprend, au lieu de recopier ce qui est déjà là.

Le dossier est marqué et reconnu. Un petit fichier repère identifie le stock : si vous rebranchez le disque plus tard ou déplacez le dossier à la main, vous pouvez y repointer MailVault, et MailVault refusera un dossier qui appartient à un autre stock ou qui ne contient aucun courrier.

Si le disque n'est pas branché, MailVault signale le stock de courrier comme indisponible, au lieu de commencer discrètement une seconde archive à l'emplacement par défaut et de vous laisser avec deux copies à moitié complètes. Rebranchez le disque, ou sélectionnez à nouveau le dossier. Vous pouvez aussi revenir à l'emplacement par défaut à tout moment — le courrier reste où il est tant que vous ne le déplacez pas.

À ne pas confondre avec une seconde copie. Ceci change l'endroit où vit le stock actif. Un emplacement de sauvegarde externe y ajoute une copie froide supplémentaire. Utiliser les deux — le stock de courrier sur un SSD externe rapide, la copie froide sur un NAS — est une configuration raisonnable.

Parce qu'il n'y a pas de dictionnaire orthographique sur la machine. macOS et Windows en fournissent un avec le système ; sous Linux, le dictionnaire vient de votre distribution, et une installation de bureau minimale n'en a souvent aucun. MailVault vérifie l'orthographe via WebKitGTK, qui consulte les mots via enchant et hunspell — il ne peut donc souligner qu'une fois un dictionnaire hunspell installé.

Le bouton de la barre d'outils du message vous dit dans quel cas vous êtes. Avec un dictionnaire installé, il active et désactive les soulignements, et MailVault retient le réglage. Sans dictionnaire, il ouvre ces mêmes instructions au lieu de faire semblant d'être un interrupteur.

Installez un dictionnaire pour votre langue :

Debian, Ubuntu, Mint
sudo apt install hunspell-en-us
Fedora
sudo dnf install hunspell-en
Arch, Manjaro
sudo pacman -S hunspell-en_us
openSUSE
sudo zypper install myspell-en_US

Remplacez le code de langue par le vôtre — hunspell-de-de, hunspell-fr, et ainsi de suite. Vous pouvez en installer plusieurs ; MailVault contrôle avec celui qui correspond à la langue de votre système, et avec tous si aucun ne correspond. Redémarrez MailVault ensuite — le correcteur est mis en place au démarrage de l'application.

Le paquet snap est un cas particulier. Un snap strictement confiné ne voit pas les dictionnaires installés sur l'hôte : il embarque donc sa propre copie. Si le snap signale l'absence de dictionnaire, installez plutôt le paquet .deb — il utilise les dictionnaires déjà présents sur votre système.
