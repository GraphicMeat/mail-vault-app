Stockage et votre coffre

Où MailVault range votre courrier sur le disque, pourquoi il utilise .eml et Maildir, et comment déplacer le coffre vers un autre disque.

Où mes e-mails sont-ils stockés ?

Votre coffre est un dossier de fichiers .eml standard organisés au format Maildir sur votre Mac ou votre machine Linux — un fichier par e-mail, aucune base de données requise. Vos données ne quittent jamais votre ordinateur et ne sont jamais envoyées vers un service cloud. Comme .eml est un standard universel, vos e-mails peuvent être ouverts par Apple Mail, Thunderbird, Outlook ou n'importe quel autre client de messagerie — vous n'êtes jamais captif de MailVault.

The exact folder

MailVault is a sandboxed app, so on macOS the vault sits inside the app's own container — not directly under ~/Library/Application Support, which is where most people look first:

~/Library/Containers/com.mailvault.app/Data/Library/Application Support/com.mailvault.app/

On Linux it is ~/.local/share/com.mailvault.app/ for the .deb package, and ~/snap/mailvault/current/.local/share/com.mailvault.app/ for the Snap.

Searching the drive for com.mailvault.app usually finds nothing, and that is expected: ~/Library is hidden in Finder and Spotlight does not index it. Open it by path instead.

Opening the hidden Library folder on a Mac

  1. Go to Folder. In Finder press Shift + Command + G, type ~/Library — or paste the full path above to land straight in the vault — and press Return.
  2. The Go menu. In Finder, open the Go menu and hold Option: Library appears in the list while the key is held.
  3. Show it for good. Finder → Go → Home (Shift + Command + H), then press Command + J and tick Show Library Folder. It stays visible from then on.
  4. Terminal. One command opens the vault in Finder:
open ~/Library/Containers/com.mailvault.app/Data/Library/Application\ Support/com.mailvault.app

MailVault also tells you the folder it is actually using: Settings → Backup → Where your mail is stored. If you have moved the vault to another drive, that is the path to open — the one above is only the default.

Structure des dossiers :

com.mailvault.app/
├── accounts.json                 ← which address each account folder holds
└── Maildir/
    └── 43483205-7efc-4f79-…/     ← one folder per account
        └── INBOX/
            ├── local-index.json  ← cached list for fast loading
            └── cur/
                ├── 101:2,.eml    ← a message, no flags set
                └── 102:2,AS.eml  ← archived + seen

Que sont les fichiers .eml et Maildir ? Pourquoi est-ce important ?

.eml (RFC 5322) est le format standard d'Internet pour les messages électroniques. Chaque e-mail — en-têtes, corps et pièces jointes — est stocké dans un seul fichier texte autonome. Contrairement aux bases de données propriétaires, les fichiers .eml s'ouvrent dans n'importe quel client de messagerie (Apple Mail, Thunderbird, Outlook) et se lisent dans n'importe quel éditeur de texte.

Maildir est une structure de dossiers éprouvée pour stocker du courrier, utilisée par les serveurs de messagerie depuis des décennies. Chaque e-mail est un fichier : il n'y a donc pas de base de données unique qui puisse se corrompre — si un fichier est endommagé, le reste de votre archive n'est pas touché. Ensemble, .eml + Maildir garantissent que vos e-mails restent lisibles dans le temps, portables, et jamais captifs d'une seule application.

Indicateurs dans le nom de fichier :

Each message is named <uid>:2,<flags>.eml, the standard Maildir naming — the characters after 2, track status: A = Archived, S = Seen, R = Replied, F = Flagged. So 102:2,AS.eml is message 102, archived and seen.

Puis-je accéder à mes e-mails hors ligne ?

Oui. Une fois vos e-mails synchronisés, ils sont stockés en local et vous pouvez tous les lire, les rechercher et les parcourir sans connexion Internet. Internet ne vous sert qu'à synchroniser les nouveaux e-mails ou à envoyer des messages.

Comment les pièces jointes sont-elles gérées ?

Les pièces jointes sont intégrées à chaque fichier .eml sous forme de parties MIME — elles ne sont pas stockées dans des fichiers séparés. Quand vous ouvrez un e-mail, le moteur Rust de MailVault analyse la structure MIME et en extrait les pièces jointes à la volée. Vous pouvez Ouvrir, Enregistrer sous ou Afficher dans le dossier n'importe quelle pièce jointe directement depuis le lecteur d'e-mail. Les pièces jointes extraites sont mises en cache temporairement, pour être rouvertes rapidement.

Puis-je stocker mon courrier ailleurs que dans le dossier d'application par défaut ?

Oui. Par défaut, MailVault garde son stockage de courrier dans son propre dossier Application Support, sur votre disque de démarrage. Vous pouvez déplacer ce stockage vers n'importe quel dossier sur n'importe quel support — un SSD externe, un second disque interne — ce qui compte dès qu'une archive atteint des dizaines de gigaoctets.

Seules les données de courrier bougent : les messages, les caches d'en-têtes, le cache des pièces jointes et les listes de dossiers. Les comptes, les réglages et les journaux restent dans le dossier propre à l'application, de sorte que MailVault peut toujours démarrer assez loin pour vous signaler qu'un disque manque et vous redemander le dossier.

Le déplacement est vérifié avant la moindre suppression. MailVault copie tout vers le nouveau dossier, contrôle que chaque fichier est bien arrivé à la bonne taille, bascule, et seulement ensuite retire les originaux. Un déplacement interrompu par une déconnexion ou un plantage laisse le stock actuel intact ; relancez-le et il reprend, au lieu de recopier ce qui est déjà là.

Le dossier est marqué et reconnu. Un petit fichier repère identifie le stock : si vous rebranchez le disque plus tard ou déplacez le dossier à la main, vous pouvez y repointer MailVault, et MailVault refusera un dossier qui appartient à un autre stock ou qui ne contient aucun courrier.

Si le disque n'est pas branché, MailVault signale le stock de courrier comme indisponible, au lieu de commencer discrètement une seconde archive à l'emplacement par défaut et de vous laisser avec deux copies à moitié complètes. Rebranchez le disque, ou sélectionnez à nouveau le dossier. Vous pouvez aussi revenir à l'emplacement par défaut à tout moment — le courrier reste où il est tant que vous ne le déplacez pas.

À ne pas confondre avec une seconde copie. Ceci change l'endroit où vit le stock actif. Un emplacement de sauvegarde externe y ajoute une copie froide supplémentaire. Utiliser les deux — le stock de courrier sur un SSD externe rapide, la copie froide sur un NAS — est une configuration raisonnable.

Qu'est-ce que l'emplacement de sauvegarde externe (deuxième copie) ?

MailVault garde toujours une copie de travail de votre courrier dans son propre espace de stockage — c'est elle que vous lisez, fouillez et ouvrez. Un emplacement de sauvegarde externe ajoute une seconde copie, indépendante, sur un support que vous maîtrisez : un SSD externe, un partage NAS ou un dossier synchronisé.

  • Écrite en même temps que la copie de travail. Pendant une sauvegarde, chaque message est enregistré aux deux endroits, dans la même disposition .eml + Maildir — la seconde copie s'ouvre donc dans Apple Mail, Thunderbird ou n'importe quel autre client, sans MailVault.
  • Un stockage froid, pas un miroir. L'application ne le lit jamais au quotidien. Les e-mails supprimés sur le serveur, ou retirés depuis MailVault, restent dans la copie externe.
  • Les indicateurs de lecture et d'écriture survivent dans les deux sens. Les copies sont réconciliées avant chaque exécution : un message que vous avez lu reste lu.
  • Indépendante de l'application. Si cet ordinateur meurt ou si vous désinstallez MailVault, le dossier externe reste une archive de courrier complète, qui se décrit elle-même.

Réglez cela dans Paramètres → Sauvegarde → « Seconde copie — stockage froid externe » et choisissez le dossier que vous voulez. Sur macOS, MailVault enregistre un signet à portée de sécurité pour ce dossier : l'accès survit donc aux redémarrages et aux mises à jour de l'application — un simple chemin ne le ferait pas. Un badge d'état affiche Prêt, Réautorisation nécessaire, Indisponible ou Accès refusé, et la réautorisation se fait en un clic.

Si le support est débranché en cours de sauvegarde, la copie de travail va tout de même au bout et MailVault indique combien de messages n'ont pas atteint la copie externe. L'exécution suivante les recopie — rien n'est perdu, et l'échec n'est jamais silencieux.
