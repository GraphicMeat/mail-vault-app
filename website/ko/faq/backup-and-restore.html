백업과 복원

MailVault가 메일을 어떻게 보관하는지, 보관한 뒤 삭제하면 서버 사본이 어떻게 되는지, 자동 백업이 언제 실행되는지, 볼트를 내보내고 다시 가져오는 방법.

MailVault는 메일을 어떻게 백업합니까?

MailVault는 IMAP, 개인 Outlook.com 계정용 Microsoft Graph 또는 JMAP으로 메일 서버에 연결합니다. 메일을 보관하려면 필요한 메시지를 명시적으로 보관하거나 모든 메일 (서버에서 내려받기)로 수동 백업을 실행합니다. 기본 Maildir 저장 형식에서는 저장된 메시지가 컴퓨터의 Maildir 폴더에 표준 .eml 파일로 저장되며 EML 지원 앱에서 읽을 수 있습니다. 선택 사항인 JMAP 저장소는 원본 바이트를 JSON 레코드와 함께 보관하고 동일한 메시지의 중복을 제거합니다. 서버 사본을 삭제하기 전에 보관된 메시지와 첨부파일을 열고, 필요한 폴더와 날짜 범위가 포함되어 있는지 확인하고, 별도의 백업 위치에 두 번째 사본이 있는지도 검증해야 합니다. 받은 편지함이나 캐시에 메시지가 표시된다는 사실만으로 보관이 완료되었다고 볼 수는 없습니다.

메일을 보관하면 어떻게 됩니까?

보관은 (아직 캐시되지 않았다면) 서버에서 메일 전체를 내려받아, 파일 이름에 A(Archived) 플래그를 붙인 .eml 파일로 디스크에 저장합니다. 메일이 이미 로컬에 캐시되어 있다면 MailVault는 기존 로컬 메시지를 보관됨으로 표시합니다. 보관한 메일은 볼트 보기에 나타나고 백업에도 포함됩니다. 서버 사본은 사용자가 직접 지울 때까지 그대로입니다.

보관 후 서버에서 삭제하면 어떻게 됩니까?

Premium 기능인 보관 후 삭제는 세 단계를 차례로 실행합니다. 메시지를 .eml 파일로 볼트에 복사하고, 사본이 실제로 있는지 확인한 다음, 그제야 서버에서 삭제합니다. 확인을 통과하지 못한 메시지는 서버에 남습니다 — 복사에 실패해도 원본을 잃지 않습니다. 작업이 끝나면 해당 행에 유일한 사본이 표시됩니다. 그 메시지가 남아 있는 곳은 볼트뿐이라는 뜻이며, 백업 드라이브를 연결해 두라는 신호이기도 합니다.

역시 Premium인 보관, 백업 후 삭제는 사본을 하나 더 만듭니다. 각 메시지를 백업 폴더에도 복사하고, 두 사본을 모두 확인한 뒤, 둘 다 확인된 메시지만 서버에서 지웁니다. 먼저 백업 폴더를 정해 두어야 합니다. 드라이브에 접근할 수 없거나 사본이 일치하지 않으면 해당 메시지는 하나도 삭제되지 않으며, 결과 화면에 서버에 남은 메시지 수가 표시됩니다.

설정 → 백업 및 복원 → 보관 후 삭제에 있는 두 작업(둘 다 Premium)은 선택한 메시지 대신 계정 전체를 같은 방식으로 처리합니다. 보관, 백업 후 서버에서 삭제는 지정한 범위의 메일을 볼트와 백업 폴더에 저장하고, 보관 후 서버에서 삭제는 볼트에만 저장합니다. 폴더와 기간(모든 기간, 올해, 작년, 2년보다 오래된 메일, 또는 직접 고른 연도), 모두 저장한 뒤에 삭제할지 메일이 저장될 때마다 삭제할지, 휴지통으로 이동할지 휴지통으로 이동한 뒤 비울지를 고르면, 확인하기 전에 무엇이 제거되는지 요약이 표시됩니다. 메일을 제거하기 전에 모든 사본을 확인하고, 작업은 백그라운드에서 그리고 다시 시작한 뒤에도 계속되며, 일일 다운로드 한도나 Gmail 자체 한도에 걸리면 실패하는 대신 기다립니다.

서버에서 메일을 삭제하면 어떻게 됩니까?

먼저 보관한 메시지는 서버가 나중에 무엇을 하든 볼트에 그대로 남습니다 — 이 제품의 핵심이 바로 그것입니다. 보관하지 않은 메시지는 서버 사본과 함께 사라집니다. 그래서 MailVault는 삭제하기 전에 모든 메시지의 상태를 각 행에 보여 줍니다. 서버에 있는지, 볼트에 있는지, 둘 다인지. 안전한 방법은 보관 후 삭제(Premium)로, 각 메시지를 볼트에 복사하고 거기서 확인한 다음에 서버에서 제거합니다.

서버에서 선택한 이메일을 보관한 뒤 삭제하려면 어떻게 합니까?

한 계정에서 직접 고른 일부를 정리하고 싶을 때는 이메일 일괄 작업을 사용합니다. 1년치, 특정 기간, 직접 선택한 묶음이 해당합니다. 서버 보기를 열고 메시지 선택…을 누른 다음 연도를 고르고 다음을 눌러 작업을 선택합니다. 아래 두 방법은 모두 Premium 기능이며, 서버에서 무언가를 지우기 전에 모든 사본을 확인합니다.

  • 보관 후 삭제는 각 이메일을 보관함에 복사하고, 거기서 확인한 다음 서버에서 제거합니다. 이후에는 보관함이 유일한 사본이 됩니다.
  • 보관, 백업 후 삭제는 각 이메일을 백업 폴더에도 복사하고, 두 사본을 모두 확인한 다음 서버에서 제거합니다. 설정 → 백업 및 복원 → 백업 설정에서 백업 폴더를 지정하기 전에는 “먼저 백업 폴더를 선택하세요”라는 안내와 함께 회색으로 비활성화되어 있습니다.

확인을 통과하지 못한 이메일은 서버에 남으며, 남은 이메일 수가 결과에 표시됩니다. 작업이 끝나면 서버의 이메일 수는 제거된 만큼 줄어들고, 같은 이메일이 보관함 보기에 표시됩니다.

모든 클릭을 스크린샷으로 보고 싶으신가요? 단계별 안내를 확인하세요. 선택 항목이 아니라 계정 전체를 정리하려면 설정 방법을 사용하세요.

설정에서 계정 전체를 보관한 뒤 삭제하려면 어떻게 합니까?

설정 → 백업 및 복원 → 보관 후 삭제를 엽니다. 두 가지 Premium 작업은 계정 전체를 한 번에 처리합니다. 보관, 백업 후 서버에서 삭제(보관함과 백업 폴더)와 보관 후 서버에서 삭제(보관함만)입니다. 설정 버튼을 누르고 제거할 항목을 고른 다음 요약을 읽고, 확인란에 체크한 뒤 시작을 누릅니다.

메시지를 선택하지 않고 설정을 쓰는 이유

  • 계정 전체를 대상으로 합니다. 폴더(또는 전체 계정)에 체크하고 모든 기간, 올해, 작년, 2년보다 오래된 메일 또는 직접 고른 연도를 선택합니다. 손으로 하나씩 고를 필요가 없습니다.
  • 비용을 먼저 확인합니다. 요약에는 폴더별, 연도별 이메일 수와 용량(MB), 이미 보관함이나 백업 드라이브에 있는 이메일 수, 아직 내려받아야 할 양이 표시되고, 일일 다운로드 한도를 설정했거나 Gmail을 사용하면 대략 며칠이 걸리는지도 표시됩니다.
  • 위험도를 직접 정합니다. 모두 다운로드하고 확인한 뒤에 삭제하거나(가장 안전), 이메일이 저장될 때마다 삭제해 작업이 진행되는 동안 공간을 확보합니다.
  • 서버에서 제거하는 방식을 고릅니다. 휴지통으로 이동하거나, 휴지통으로 이동한 뒤 비웁니다. 비우기는 이 작업이 옮긴 이메일만 제거하고 휴지통의 나머지는 건드리지 않습니다.
  • 백그라운드에서 실행됩니다. 진행 패널이 작업을 따라가는 동안에도 MailVault를 계속 사용할 수 있습니다. 일시 중지, 재개, 취소할 수 있고, 앱을 다시 시작해도 작업은 계속되며, 일일 한도나 Gmail의 한도에 걸리면 실패하는 대신 기다립니다.
  • 이메일을 제거하기 전에 모든 사본을 확인합니다. 확인을 통과하지 못한 이메일은 서버에 남고, 패널에 그 이유가 표시됩니다.

알아 두세요: 라벨이 여러 개인 이메일은 모든 라벨에서 제거되고, 이미 휴지통에 있는 이메일은 저장한 뒤 휴지통에 그대로 둡니다. 몇 년치를 빠르게 정리할 때는 일괄 작업 방법이 더 빠릅니다. 메일함 전체에는 설정이 더 안전하고 세밀하게 제어할 수 있는 방법입니다.

단계별 안내: 서버에서 보관 후 삭제, 스크린샷 포함

MailVault Premium이 필요합니다. 백업 방식을 쓰려면 먼저 백업 폴더를 지정하세요(설정 → 백업 및 복원 → 백업 설정). 스크린샷에는 MailVault의 가상 데모 메일함을 사용했습니다.

방법 1: 이메일 일괄 작업

  1. 계정의 서버 보기를 엽니다.

  2. 목록 도구 모음에서 메시지 선택…을 선택합니다. 이메일 일괄 작업에 계정의 연도가 나열됩니다.

  3. 연도를 고릅니다. MailVault가 선택되는 이메일 수를 표시합니다.

  4. 다음을 누르고 작업을 선택합니다. 보관 후 삭제 또는 보관, 백업 후 삭제입니다.

  5. 대화 상자 아래쪽의 작업 버튼을 누른 다음 확인 내용을 읽습니다. 복사하지 못한 메일은 서버에 남습니다.

  6. 확인합니다. 진행 상황이 창 모서리에 표시됩니다. 다운로드, 확인(및 백업), 삭제 순입니다.

  7. 작업 완료가 표시되면 서버의 이메일 수가 줄어든 것입니다. 보관함 보기를 열면 이메일이 그대로 있습니다.

방법 2: 설정 → 백업 및 복원 → 보관 후 삭제

  1. 설정을 열고 백업 및 복원을 선택합니다.

  2. 보관 후 삭제 탭을 엽니다. 계정을 선택한 다음 보관, 백업 후 서버에서 삭제 또는 보관 후 서버에서 삭제에서 설정을 누릅니다.

  3. 제거할 폴더 또는 계정 전체를 선택합니다.

  4. 기간을 선택합니다. 모든 기간, 올해, 작년, 2년보다 오래된 메일 또는 연도 선택입니다.

  5. 삭제 시점과 방법을 선택합니다. 모두 다운로드한 후 또는 메일이 저장될 때마다, 그리고 휴지통으로 이동 또는 휴지통으로 이동 후 비우기입니다.

  6. 요약을 읽습니다. 폴더별, 연도별 이메일 수와 용량, 이미 보관함이나 백업 드라이브에 있는 이메일, 아직 다운로드할 양입니다.

  7. 확인란에 체크하고 시작을 누릅니다.

  8. 작업은 백그라운드에서 실행됩니다. 설정을 닫은 뒤 진행 패널에서 확인하면 됩니다.

  9. 패널에 완료됨이 표시되면 보관함 보기에서 이메일을 확인하고, 서버 보기에서 이메일이 사라졌는지 확인합니다.

설정에서는 시작하기 전에 더 세밀하게 제어하고 요약을 확인할 수 있어, 계정 전체에는 설정을 권장합니다. 1년치만 정리한다면 일괄 작업이 더 빠릅니다. 두 방법은 설정 문서에서 비교해 보세요.

백업과 복원은 어떻게 작동합니까?

MailVault는 메일을 모든 .eml 파일과 manifest.json이 든 ZIP 아카이브로 내보냅니다. 이 manifest는 내부 ID가 아니라 이메일 주소로 메일과 계정을 이어 주므로, 백업을 다른 설치 환경으로도 그대로 옮길 수 있습니다. 모든 메일을 내보낼지 보관된 것만 내보낼지 고를 수 있습니다. 가져오기는 몇 번을 해도 결과가 같습니다 — 로컬에 이미 있는 메일은 중복되지 않습니다. 백업에 아직 설정하지 않은 계정의 메일이 들어 있으면 MailVault가 그 계정을 자동으로 만들어 줍니다(설정에서 비밀번호만 다시 넣으면 됩니다).

자동 백업이 실행되는 시각을 정할 수 있나요?

네, Premium에서 가능합니다. 설정 → 백업 및 복원 → 백업 일정에는 네 가지 주기가 있습니다. 매시간, 하루 한 번, 일주일에 한 번, 그리고 지정한 시각에입니다. “지정한 시각에”를 고르면 24시간 전체 그리드가 나타납니다. 원하는 시각을, 예를 들어 07, 12, 22를 누르면 MailVault가 각 시각 정각에 백업하고 그 사이에는 실행하지 않습니다. 모든 주기는 앱이 유휴 상태일 때만 실행되므로 작업 중에 백업이 시작되지 않습니다.

지정한 시각은 Time Machine처럼 다른 프로그램이 자체 일정으로 이미 사용하는 외장 드라이브의 볼트나 백업 사본을 위한 기능입니다. 그 드라이브가 비어 있는 시각을 고르세요. 선택한 시각이 왔을 때 MailVault가 다른 작업 중이면 그 회차는 나중에 따라잡지 않고 건너뛰며, 다음 실행은 그다음 선택한 시각입니다.
