저장소와 볼트

  • 오프라인에서도 메일을 볼 수 있습니까?

  • 외부 백업 위치(두 번째 사본)란 무엇입니까?
  • 보관함 저장 형식을 변경할 수 있나요?

MailVault의 메일 저장 위치, Maildir과 JMAP 저장 형식의 차이, 보관함을 이동하거나 변환하는 방법.

메일은 어디에 저장됩니까?

기본 볼트는 컴퓨터에서 표준 .eml 파일을 Maildir 형식으로 정리한 폴더입니다 — 메일 한 통당 파일 하나이며 메일 저장용 데이터베이스가 필요 없습니다. MailVault는 볼트를 자체 서버에 업로드하지 않습니다. 메일 동기화는 계속 제공업체가 처리하며 클라우드 동기화 폴더나 선택한 원격 AI를 쓰면 사용자가 고른 서비스가 관여합니다. .eml은 널리 지원되는 메일 형식이므로 Apple Mail, Thunderbird, Outlook 등 EML 지원 앱에서 열 수 있고 MailVault에 종속되지 않습니다.

정확한 폴더

샌드박스 macOS 빌드에서 기본 볼트는 앱 자체 컨테이너 안에 있습니다 — 많은 사람이 먼저 찾는 ~/Library/Application Support 바로 아래가 아닙니다:

~/Library/Containers/com.mailvault.app/Data/Library/Application Support/com.mailvault.app/

Linux에서는 .deb 패키지의 경우 ~/.local/share/com.mailvault.app/, Snap의 경우 ~/snap/mailvault/current/.local/share/com.mailvault.app/입니다.

드라이브에서 com.mailvault.app을 검색해도 대개 아무것도 나오지 않으며, 이는 정상입니다: ~/Library는 Finder에서 숨겨져 있고 Spotlight도 색인하지 않습니다. 대신 경로로 여십시오.

Mac에서 숨겨진 라이브러리 폴더 열기

  1. 폴더로 이동. Finder에서 Shift + Command + G를 누르고 ~/Library를 입력한 다음 — 위의 전체 경로를 붙여 넣으면 볼트로 바로 이동합니다 — Return을 누릅니다.
  2. 이동 메뉴. Finder에서 이동 메뉴를 열고 Option을 누르고 있으면 키를 누르는 동안 라이브러리가 목록에 나타납니다.
  3. 계속 표시하기. Finder → 이동 → 홈(Shift + Command + H)으로 간 다음 Command + J를 누르고 라이브러리 폴더 보기를 선택합니다. 그 뒤로는 계속 보입니다.
  4. 터미널. 명령 하나로 볼트를 Finder에서 엽니다:
open ~/Library/Containers/com.mailvault.app/Data/Library/Application\ Support/com.mailvault.app

MailVault는 실제로 사용 중인 폴더도 알려줍니다: 설정 → 백업 및 복원 → 백업 설정 → 메일 저장 위치. 볼트를 다른 드라이브로 옮겼다면 그 경로를 열어야 합니다 — 위의 경로는 기본값일 뿐입니다.

디렉터리 구조:

com.mailvault.app/
├── accounts.json                 ← which address each account folder holds
└── Maildir/
    └── 43483205-7efc-4f79-…/     ← one folder per account
        └── INBOX/
            ├── local-index.json  ← cached list for fast loading
            └── cur/
                ├── 101:2,.eml    ← a message, no flags set
                └── 102:2,AS.eml  ← archived + seen

내 메일 중 얼마나 이 컴퓨터에 남나요?

설정 → 저장소 → 다운로드 모드에서 정하며, 설정 → 계정 → 고급에서 계정마다 다른 모드를 지정할 수도 있습니다.

  • 필요할 때는 메시지를 열 때 가져오고 보관하지 않습니다. 전체 텍스트 검색은 이미 이 컴퓨터에 있는 것만 대상으로 합니다.
  • 최근 메일 보관은 기본 모드로, 최근 1, 3, 6, 12개월을 보관하고 그보다 오래된 캐시 사본은 이 컴퓨터에서 삭제하며 서버에는 사본이 남습니다.
  • 색인만은 같은 기간을 다운로드해 검색용으로 색인한 뒤 삭제하므로, 메시지를 열면 전체 메시지가 다운로드되는 동안 바로 미리보기가 표시됩니다.
  • 모두 보관 Premium은 모든 폴더와 전체 기록을 백그라운드에서 다운로드해 보관합니다.

어떤 모드도 백업과 보관 처리된 메일을 삭제하지 않으며, Premium 구독이 만료되어도 아무것도 삭제되지 않습니다.

.eml 파일과 Maildir이란 무엇이며, 왜 중요합니까?

.eml(RFC 5322)은 메일 메시지의 인터넷 표준 형식입니다. 기본 Maildir 형식에서는 각 메일의 헤더, 본문, 첨부 파일을 하나의 독립된 텍스트 파일에 저장합니다. 독점 데이터베이스와 달리 .eml 파일은 EML을 지원하는 메일 앱(Apple Mail, Thunderbird 등)에서 열 수 있고 텍스트 편집기로도 읽을 수 있습니다.

Maildir은 메일 서버가 수십 년째 써 온, 검증된 메일 저장용 디렉터리 구조입니다. 메일 하나가 파일 하나이므로 손상될 수 있는 단일 데이터베이스가 없습니다 — 파일 하나가 망가져도 나머지 보관본은 영향을 받지 않습니다. .eml과 Maildir을 함께 쓰면 메일이 앞으로도 열리고, 이식 가능하며, 어떤 앱 하나에도 묶이지 않습니다.

파일 이름 플래그:

macOS와 Linux에서 각 Maildir 메시지의 이름은 <uid>:2,<flags>.eml입니다. 표준 Maildir 명명 방식으로 2, 뒤의 문자가 상태를 나타냅니다. A = 보관됨, S = 읽음, R = 답장함, F = 플래그 지정입니다. 따라서 102:2,AS.eml은 보관되고 읽은 메시지 102입니다. Windows 파일 이름에는 콜론을 쓸 수 없으므로 MailVault는 :2, 대신 ;2,를 사용합니다.

오프라인에서도 메일을 볼 수 있습니까?

볼 수 있습니다. 메일이 한 번 동기화되면 로컬에 저장되므로 인터넷 연결 없이도 전부 읽고, 검색하고, 살펴볼 수 있습니다. 인터넷은 새 메일을 동기화하거나 메일을 보낼 때만 필요합니다.

첨부파일은 어떻게 처리됩니까?

첨부파일은 각 .eml 파일 안에 MIME 파트로 들어 있습니다 — 별도 파일로 저장되지 않습니다. 메일을 열면 MailVault의 Rust 백엔드가 MIME 구조를 해석해 그때그때 첨부파일을 꺼냅니다. 메일 뷰어에서 바로 어떤 첨부파일이든 Open, Save As, Show in Folder할 수 있습니다. 꺼낸 첨부파일은 다시 열 때 빠르도록 잠시 캐시됩니다.

기본 애플리케이션 폴더가 아닌 다른 곳에 메일을 저장할 수 있습니까?

가능합니다. 기본적으로 MailVault는 시동 디스크에 있는 앱 전용 Application Support 폴더 안에 메일 저장소를 둡니다. 이 저장소는 어떤 드라이브의 어떤 폴더로든 옮길 수 있습니다 — 외장 SSD든 두 번째 내장 디스크든 상관없습니다. 보관본이 수십 기가바이트로 커지면 중요한 선택지입니다.

메일 데이터만 옮겨집니다: 메시지, 헤더 캐시, 첨부파일 캐시, 폴더 목록입니다. 계정과 설정, 로그는 앱 자체 폴더에 남으므로, MailVault는 언제나 드라이브가 없다고 알리고 폴더를 다시 물어볼 수 있을 만큼은 시작됩니다.

무엇이든 지우기 전에 이동을 검증합니다. MailVault는 모든 것을 새 폴더로 복사하고, 파일마다 올바른 크기로 도착했는지 확인하고, 저장소를 전환한 다음, 그때에야 원본을 지웁니다. 연결이 끊기거나 앱이 죽어 중단된 이동은 현재 저장소를 그대로 남겨 둡니다. 다시 실행하면 이미 옮긴 것을 다시 복사하지 않고 이어서 진행합니다.

폴더에는 표식이 찍히고, 그것을 알아봅니다. 작은 표식 파일이 그 저장소를 식별하므로, 나중에 드라이브를 다시 연결하거나 폴더를 손으로 옮겨도 MailVault를 그쪽으로 다시 가리킬 수 있습니다. 또 MailVault는 다른 저장소에 속하거나 메일이 들어 있지 않은 폴더는 거부합니다.

드라이브가 연결되어 있지 않으면 MailVault는 기본 위치에 조용히 두 번째 보관본을 만들어 반쯤 찬 사본 두 개를 남기는 대신, 메일 저장소를 쓸 수 없다고 알립니다. 드라이브를 다시 연결하거나 폴더를 다시 고르십시오. 언제든 기본 위치로 되돌릴 수도 있습니다 — 메일은 옮기기 전까지 있던 자리에 그대로 있습니다.

두 번째 사본과는 다릅니다. 이것은 실사용 저장소가 어디에 있는지를 바꿉니다. 외부 백업 위치는 그 위에 보관용 사본을 하나 더 얹습니다. 둘을 함께 쓰는 것도 — 메일 저장소는 빠른 외장 SSD에, 보관용 사본은 NAS에 — 합리적인 구성입니다.

외부 백업 위치(두 번째 사본)란 무엇입니까?

MailVault는 설정한 메일 저장소에 항상 메일의 작업용 사본을 보관합니다. 메일을 읽고 검색하고 열 때 사용하는 사본입니다. 외부 백업 위치는 사용자가 관리하는 드라이브에 두 번째 독립 사본을 더합니다. 외장 SSD, NAS 공유 폴더, 동기화되는 폴더 같은 곳입니다.

  • 작업용 사본과 함께 기록합니다. 백업 중에는 각 메일을 같은 .eml + Maildir 구조로 두 위치에 저장하므로 EML을 지원하는 앱에서 MailVault 없이 개별 메시지 파일을 열 수 있습니다.
  • 거울이 아니라 보관용입니다. 앱은 평소에 그것을 읽지 않습니다. 서버에서 지워진 메일이나 MailVault 안에서 없앤 메일도 외부 사본에는 남습니다.
  • 읽음과 쓰기 플래그가 양쪽 방향으로 유지됩니다. 실행 전에 두 사본을 맞추므로, 읽은 메시지는 읽은 상태로 남습니다.
  • 앱과 무관합니다. 그 컴퓨터가 죽거나 MailVault를 지워도 외부 폴더는 그 자체로 완결된 메일 보관본으로 남습니다.

설정 → 백업 → “두 번째 사본 — 외부 보관 저장소”에서 지정하고 원하는 폴더를 고르십시오. macOS에서는 MailVault가 그 폴더에 대한 보안 범위 북마크를 저장하므로 재시작이나 앱 업데이트 뒤에도 접근이 유지됩니다 — 단순 경로였다면 그렇지 않습니다. 상태 배지가 Ready, Needs reauthorization, Unavailable, Access denied 가운데 하나를 보여 주며, 재승인은 클릭 한 번입니다.

백업 도중 드라이브가 분리되어도 작업 사본은 끝까지 완료되며, MailVault는 외부 사본에 도달하지 못한 메시지가 몇 통인지 알려 줍니다. 다음 실행에서 그 메일들을 옮겨 담습니다 — 잃는 것은 없고, 실패가 조용히 넘어가는 일도 없습니다.

보관함 저장 형식을 변경할 수 있나요?

네. 설정 > 저장소에서 Maildir과 JMAP 저장 형식 사이를 변환할 수 있습니다. 기본 형식인 Maildir은 메시지마다 하나의 .eml 파일을 사용합니다. JMAP 저장 형식은 원본 메시지 바이트와 표준 JMAP JSON 레코드를 보관하며, 여러 폴더에 있는 동일한 메시지를 한 번만 저장합니다. 이전 파일을 따로 보관할지, 각 메시지를 검증한 뒤 삭제할지 선택할 수 있습니다. 변환은 백그라운드에서 실행되며 재시작 후에도 이어서 진행됩니다. 저장 형식 선택은 계정이 IMAP, Microsoft Graph, JMAP 중 무엇을 사용하는지와 무관합니다.
