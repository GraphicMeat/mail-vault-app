로컬 이메일 저장과 클라우드 이메일: 어떤 사본을 직접 관리할 수 있을까요?

로컬 이메일 저장과 클라우드 이메일은 같은 문제의 서로 다른 부분을 해결합니다. 메일 서비스는 메시지를 받고 현재 메일상자를 여러 기기에서 사용할 수 있게 합니다. 로컬 보관함은 자신의 컴퓨터에 보존하고 직접 살펴볼 수 있는 사본을 제공합니다. 많은 사람에게 둘 다 필요합니다.

배달, 동기화, 보존을 구분하기

배달은 메시지를 계정으로 전달합니다. 동기화는 클라이언트와 서버 사이의 변경을 반영합니다. 보존은 나중을 위해 사본을 남깁니다. 메시지를 서버의 ‘보관’ 폴더로 옮기면 메일상자 안의 위치가 바뀝니다. Mac에 별도 사본이 자동으로 생기는 것은 아닙니다.

MailVault에서 직접 보관한 메시지는 로컬 Maildir 트리에 .eml 파일로 저장됩니다. 서비스 제공업체에서 메시지를 삭제해도 저장한 사본은 남길 수 있습니다. 서버 메일을 삭제하기 전에 보관이 완료되었는지, 메시지와 첨부 파일이 열리는지 확인합니다. 이 파일 구조 설명은 기본 Maildir 형식을 기준으로 합니다. 설정 → 저장소에서는 원본 메시지 바이트를 JSON 레코드와 함께 보관하고 동일한 메시지의 중복을 제거하는 JMAP 저장소도 선택할 수 있습니다.

실제 장단점 비교하기

  • 접근. 클라우드 메일은 연결된 여러 기기에서 편리합니다. 로컬 보관함은 그것을 저장한 컴퓨터에서 사용할 수 있으며, 전체 메시지가 저장되어 있으면 오프라인에서도 이용할 수 있습니다.
  • 관리 권한. 서버 사본은 서비스 제공업체가 관리합니다. 로컬 보관 파일과 백업의 위치는 직접 선택합니다.
  • 복구. 계정을 사용할 수 없게 되면 보존한 로컬 사본이 도움이 됩니다. 별도 백업은 컴퓨터 자체를 잃는 상황에 대비합니다.
  • 저장 공간. 서버 할당량과 로컬 디스크 공간은 별개의 한도입니다. 메일을 다운로드하는 것만으로 서버 공간이 늘지는 않습니다. 저장을 확인한 서버 사본을 삭제해야 공간이 확보됩니다.
  • 유지 관리. 서비스 제공업체는 자신의 서비스를 운영합니다. 로컬 저장 장치를 정상 상태로 유지하고 보호하며 백업을 확인하는 일은 사용자 몫입니다.

개인정보 보호는 전체 구성에 달려 있습니다

로컬 검색은 보관함 검색을 자신의 컴퓨터 안에서 처리합니다. 그렇다고 일반 이메일에 종단간 암호화가 적용되거나 서비스 제공업체가 새 메일을 처리하지 않게 되는 것은 아닙니다. 로컬 파일도 무단 접근으로부터 보호해야 합니다. 보관함을 클라우드 동기화 폴더에 두면 해당 폴더의 서비스도 보관함의 또 다른 저장 장소가 됩니다.

클라우드 서비스마다 접근 제어, 암호화, 보존 방식이 다릅니다. 모든 호스팅 저장소가 같다고 가정하지 말고 실제 서비스와 설정을 평가합니다. Mac 쪽의 선택에 관해서는 개인 보관함 점검 목록을 참고합니다.

두 가지를 함께 사용하는 구성

  1. 메일 수신과 발신에는 기존 서비스 제공업체를 계속 사용합니다.
  2. 보존하려는 폴더와 연도의 메일을 MailVault에 보관합니다.
  3. 연결 없이 저장한 메시지와 첨부 파일을 시험합니다.
  4. 보관함을 별도 드라이브에 백업하고 그 사본도 확인합니다.
  5. 그런 다음에야 어떤 서버 메시지를 온라인에 남길 필요가 없는지 결정합니다.

반드시 남아야 하는 것을 기준으로 선택하기

여러 기기에서 편리하게 접근하는 것이 우선이라면 그 작업에 필요한 만큼의 메일을 서비스 제공업체에 남깁니다. 계정이 닫혀도 오래된 기록을 보존해야 한다면 검증한 독립 보관함을 유지합니다. Mac이 내일 고장 날 가능성에 대비하려면 보관함에만 의존하지 말고 시험한 백업을 추가합니다.

MailVault의 수동 보관과 수동 백업은 무료입니다. Premium에는 예약 백업과 보관 및 삭제를 결합한 작업 절차가 추가됩니다. 프로젝트 하나의 기록을 보관하는 것부터 시작한 다음, 백업 선택 가이드로 전체 보관함의 복구를 계획합니다.

자신의 메일 폴더 하나로 시험해 봅니다.

무료 수동 보관, 로컬 메시지 검색, 수동 백업으로 시작합니다. 자동화가 필요해지면 요금제를 비교합니다.
