Linux에서 이메일을 EML로 백업하는 방법

이 페이지의 내용
  • 1. Linux 앱을 설치하고 계정 연결하기
  • 2. 백업하기 전에 먼저 보관하기
  • 보관한 메일을 신뢰하기 전에 검증하기
  • 3. 디스크 사본 보호하기
  • 자동화할 수 있습니까?

Linux의 이메일 백업은 제공업체에서 메일을 삭제하거나 디스크가 고장 나도 남아 있어야 합니다. 먼저 독립적인 로컬 보관함에 메시지를 보관한 뒤 다른 곳에 두 번째 사본을 보관하십시오. MailVault Linux 앱은 보관한 메일을 Maildir 폴더에 개별 EML 파일로 저장합니다. 이 파일 구조 설명은 기본 Maildir 형식을 기준으로 합니다. 설정 → 저장소에서는 원본 메시지 바이트를 JSON 레코드와 함께 보관하고 동일한 메시지의 중복을 제거하는 JMAP 저장소도 선택할 수 있습니다.

1. Linux 앱을 설치하고 계정 연결하기

다운로드 페이지의 Linux 다운로드 링크에서 시스템에 맞는 패키지와 아키텍처를 선택하십시오. 다른 배포판의 명령을 복사하는 대신 해당 페이지의 최신 설치 안내를 따르십시오. 지원되는 로그인 절차로 Gmail 또는 Microsoft 계정을 추가하거나 IMAP 제공업체가 제공한 연결 정보를 입력하십시오. 조직은 운영체제와 관계없이 접근을 제한할 수 있습니다.

2. 백업하기 전에 먼저 보관하기

  1. 받은편지함, 보낸편지함, 사용자 지정 폴더를 웹메일과 대조하십시오. 보관하려는 오래된 폴더와 라벨도 포함하십시오.
  2. 일괄 작업에서 폴더와 날짜 범위를 지정한 뒤 보관을 선택하십시오. 서버에서 메일을 제거하지 않고 로컬 사본을 만듭니다.
  3. 작업이 끝날 때까지 앱을 실행해 두십시오. 보관이 완료되었다고 판단하기 전에 실패 항목을 검토하고 누락된 메시지를 다시 시도하십시오.
  4. 보관함 소스를 선택하고 여러 연도의 메시지와 첨부 파일을 확인하십시오.

보관한 메일을 신뢰하기 전에 검증하기

  1. 메시지 소스를 서버나 전체가 아닌 보관함으로 전환하십시오. 기억나는 오래된 메시지를 검색하십시오.
  2. 네트워크 연결을 끊고 서로 다른 폴더와 연도의 보관된 메시지를 몇 개 열어 보십시오. 첨부 파일도 열어 보십시오. 목록에 제목이 보인다는 것만으로 메시지 본문이 저장되었다고 할 수는 없습니다.
  3. 설정에서 백업 및 복원을 열고 백업 내보내기를 사용하십시오. 두 번째 드라이브의 위치를 선택하십시오. ZIP에는 보관함, 계정, 설정이 포함되며 서버에만 있는 메시지는 제외됩니다.
  4. ZIP이 열리는지, .eml 파일이 들어 있는지, 보존하려던 폴더가 포함되어 있는지 확인하십시오. 중요한 메일이라면 무엇이든 삭제하기 전에 별도로 설치한 앱에서 사본을 복원해 보십시오.

3. 디스크 사본 보호하기

내보낸 백업에는 두 번째 드라이브를 사용하십시오. 같은 디스크의 다른 폴더는 디스크 고장에 대비한 보호 수단이 아닙니다. 이동식 드라이브라면 예약 실행 전에 마운트되어 있고 쓰기가 가능한지 확인하십시오. 개인 메일은 암호화된 저장소에 보관하고, 컴퓨터를 잃어버려도 접근할 수 있는 곳에 백업 복구용 인증 정보를 보관하십시오.

Maildir는 개별 메시지를 옮기기 쉽게 해 주지만, 사용 중인 보관함에는 앱 메타데이터도 있습니다. 실행 중인 앱에서는 앱의 백업/내보내기 기능을 우선 사용하십시오. 파일시스템에서 전체 보관함을 복사한다면 쓰기 도중의 파일이 복사되지 않도록 먼저 앱을 종료하십시오.
